## 0. Governing principles

Everything below is subordinate to three rulings. When a task here conflicts with one of them, the ruling wins.

**P1 — Apply, don't reorganise.** AMCR and TEATER remain authoritative in how their terms are organised and interpreted. Nothing in this workstream constitutes a change to either source vocabulary. Any actual change to AMCR needs a dedicated decision process outside this issue.

**P2 — Facets are plumbing.** They organise and prioritise the prompt. They are not semantic output and not a new taxonomy. Keep "which terms are available to the model" strictly separate from "how those terms are grouped for inference" — in the code, the config, and the output schema alike.

**P3 — Keep by default; exclude on evidence.** A TEATER branch comes out only when enrichment results show it is irrelevant or introduces systematic, otherwise unsolvable noise. Purely technical/administrative AMCR lists are the standing exception. **M11 is P3 applied:** the a-priori exclusions come back, and evidence — not anticipation — decides whether any of them goes out again.

### 2.2 Where the reinstated terms go — the one thing still to decide

Reinstating is a one-line switch per branch *only once its target facet is chosen*, and no ruling names one. **This is the tooling side's proposal, offered for ratification, not a decision taken:**

Add **two new facets**, both at `priority: 0` — below `Location & Admin` (1), so they sit last in the prompt and are the first thing truncation drops:

| New facet                       | Holds                                            | Terms |
|---------------------------------|--------------------------------------------------|------:|
| `Cultural & Geographic Context` | Q1: `zeme`, `jazyk`, 2560, 2900, 3076            |   972 |
| `Related Disciplines & Society` | Q2: 1, 288, 2557, 2558, 3091, 3094, 3549         | 1 669 |

Three reasons, in order of weight:

1. **It makes "evaluate later" mechanical.** Q2 is on probation by @motyc's own wording. One facet holding exactly Q2 means retiring it is deleting one facet block and flipping seven map values — and, crucially, the evaluation can report **per-facet accuracy**, so "did Q2 cause problems?" becomes a number rather than an argument.
2. **Priority 0 is the honest place for them.** Facet order is load-bearing: `build_system_prompt` truncates a *suffix*. Terms reinstated on probation should be the first to go when context is tight, not compete with `Chronology` for the front of the prompt.
3. **It respects P2 and M2.** Folding 2 638 named entities and neighbouring-discipline concepts into `Artefact` or `Methods` would make the facets read as a semantic claim about the sources. Two clearly-labelled context facets say what they are: plumbing.

The alternative — distributing the twelve branches across the existing eight facets — is equally cheap to implement and equally reversible, but loses (1) and (2). **If @david-spacil prefers per-branch placement, it is twelve values in `teater_branch_map`/`heslar_map` and a rebuild.**

### 2.3 The guardrail flip — already enforced, not merely documented

The replacement wording, proposed in `6.O3O4.decision-package.md` and endorsed verbatim by @david-spacil:

> *Select a geographic, ethnic or dynastic term only when the line is genuinely about it; prefer an archaeological content term otherwise.*

This replaces `llm_run.py:171`'s absolute prohibition. **The build refuses to let the two halves separate.** `_settings.geo_guardrail` declares whether the clause is in force, how to recognise it (`prompt_markers`), and which rules it reaches (`covers`); `vocab_build.py` reads `llm_run.py` and fails the build on a mismatch. All four combinations were exercised:

| Config                       | Prompt wording | Build                               |
|------------------------------|----------------|-------------------------------------|
| shipped (`active: true`)     | old            | ✅ passes                            |
| shipped (`active: true`)     | new            | ❌ *"the prompt no longer forbids…"* |
| reinstated (`active: false`) | old            | ❌ *"the prompt still forbids…"*     |
| reinstated (`active: false`) | new            | ✅ passes                            |

The outcome the decision package named as the trap — reinstating while the guardrail still forbids — is **not reachable**: it fails the build with both halves named. @motyc's "in the same change" is a mechanism here, not a convention.

### 3.2 @david-spacil's question — **yes, you read it exactly right**

> *"I put a qualifier only on the record that leaves the group, never on the ones that stay — two records sharing a qualifier build the same key, and the second one is then dropped without even keeping its id. Please tell me if I read that wrong."*

Confirmed against `vocab_sources.py:722-727`. Two records in one group carrying the **same** qualifier string build the same `"{cs} ({qualifier})"` key; the second hits `if key in pairs`, is appended to the `collisions` list and `continue`d — so it lands in **no** entry's `discarded_ids` and its id survives nowhere in the vocabulary. Reproduced directly: with a shared qualifier only `A1` and `T1` remain reachable; with distinct qualifiers all three ids survive.

That is a genuine M7 violation waiting to happen, and it is currently invisible — the drop is a warning line, not an error. **Two follow-ups, both ours:**

1. **`validate_settings()` must reject it.** Two overrides that would build the same key inside one label group is a config error, catchable statically, and belongs beside the other checks that refuse a silent no-op.
2. **Also reject a group where *every* member is qualified** — the bare label would vanish from the vocabulary entirely, which no reviewer would intend.

The convention @david-spacil adopted — qualifier only on the record that leaves — is the right one and should be written into the `taxonomy_overrides.json` comment block as the documented rule, not left as a thing you have to discover.

### D1 — The rubric *(draft it, don't decide it alone)*

`data_samples/vocab/6.D-eval.decision-package.md` frames the five questions with measured numbers; the rubric itself is still unwritten. It must answer, in writing, **before** any annotation begins:

- **Partial credit for a less-specific term.** The big one: **914 of 1 297** offered TEATER terms sit directly under an ancestor also offered — 70 % of the TEATER side, 44 % of the whole vocabulary. Every one of the 914 is **intra-facet**, so scoring the facet instead of the term is not an escape hatch. Under strict exact match, `třetihory` for `paleogén` scores what `keramika` scores: zero.
- **Either side of a composite pair counts correct** (from §4 — the rule `same_as` exists to support).
- **Does `teater_category_ids` participate, or only the label?** 470 terms (23 %) carry 2–4 ids. Recommended default: label only — the model never selects an id, so this is purely annotation cost.
- **Bracketed homonyms vs the bare label.** Now 7 splits, not 1. `bare_cs` makes leniency free; the gold workbook offers the qualified forms, so strict matching is the cheaper answer.
- **How the two keyword fields and `Nerelevantní (meta-text)` are scored.** `extracted_keywords_en` is a translation of `_cs` by construction; scoring both double-counts. Meta-text needs its own confusion cell — a real line labelled meta-text is silent data loss, a header labelled `kostel` is visible noise.

**Reinstatement adds a sixth question, and it is not optional:** with 2 638 context terms in the enum, the rubric must say whether selecting a country or a profession where the gold label is an archaeological term is *wrong* or *meta-text-adjacent*. Without that, the first scored run after the rebuild is unreadable.
