# Strategy — Issue #6: TEATER keyword extraction via local LLM

> Issue [#6](https://github.com/ufal/atrium-nlp-enrich/issues/6) · Labels: `enhancement`, `development`, `a big one` · **Status: ✍️ In progress**
> _Refreshed 2026-08-18 against repo HEAD `88d24e1` and comments 22–24 of the thread._

## Context
The pipeline is **built and benchmarked** (Phase 1, Apr–Jun): `llm_run.py` → `llm_pipeline.py` →
`llm_utils.py`, driven by `llm_config.txt`, on a **vLLM** backend with **constrained JSON
decoding** (`xgrammar`) and **automatic prefix caching**. A 13-model bake-off settled the
defaults (Qwen 3.6-27B production, Gemma 4-31B max precision).

What now keeps #6 open is **not** the model choice. @david-spacil's attempt to verify the ranking
([`#5253411317`](https://github.com/ufal/atrium-nlp-enrich/issues/6#issuecomment-5253411317))
surfaced that the target vocabulary was never pinned down: `teater_nested_vocab.json` is 100 %
AMCR despite the issue title, 779 of its 1267 terms sit in an uncurated `Other` bucket that the
prompt drops, and the evaluation has no written criteria. @K4TEL's answer
([`#5325964919`](https://github.com/ufal/atrium-nlp-enrich/issues/6#issuecomment-5325964919))
restates the task: **"defining vocabulary, including the taxonomy of the nested vocab system"**,
with the `Other` policy delegated to @motyc.

`c8dc6de` delivers the machinery and the data for that
([`#5326990876`](https://github.com/ufal/atrium-nlp-enrich/issues/6#issuecomment-5326990876)).
It does **not** change what any model sees: `VOCAB_PATH` still points at the old file. This plan
covers closing that gap and the two decisions that are not the code's to make.

## Strategic actions

### A — Adopt a vocabulary (the gap between "built" and "in use")
1. Decide the target: **`union_nested.json`** (2989 terms, AMCR ∪ TEATER, AMCR wins the 642 label
   collisions) is what @K4TEL described as the ideal end state; `amcr_nested.json` (956) is the
   conservative step that only fixes the grouping.
2. Wire it — either point `VOCAB_PATH` at the chosen file, or run
   `python3 vocab_build.py --source both --update-legacy` so the legacy path everyone already
   reads (`llm_config.txt`, the hub's `fixtures/e2e/VOCAB/`, and llm-enrich's `service/api.py`)
   carries the new content. The second option avoids a flag day; the first is more honest about
   which artifact is live.
3. Budget check before switching: the union renders to **~24.8k tokens** vs **~5.1k** today. On
   the production default (Qwen 3.6-27B, 262k window) that is ~10 % of context and is paid **once
   per run** thanks to prefix caching — not per line. Small-context registry entries (8k/32k) can
   no longer take the full vocabulary and will silently truncate a *prefix*: verify the surviving
   term count on any model below ~64k before trusting its output.
4. Re-run the **existing** litmus lines afterwards. A 6× larger enum is a different task; the
   Phase-1 scores do not transfer.

### B — Get the taxonomy reviewed by someone who knows the domain
- `heslar_map` (50 AMCR lists → 7 themes, 6 marked `__exclude__`) and `teater_branch_map`
  (12 TEATER branches) are **a starting proposal**, marked as such in `taxonomy_config.json`.
- The review artifact is **`data_samples/vocab/*_placement_audit.csv`**: one row per term with
  `cs, en, source, source_id, scheme, theme, placed_by`. A domain expert can sort by `scheme` and
  correct whole lists at once instead of judging 2989 individual terms.
- Corrections belong in `taxonomy_config.json` (or a `taxonomy_overrides.json` applied after the
  rules), never by hand-editing a generated nested file — `vocab_build.py --from-flat --check`
  exists precisely so an edit that moves the artifact is visible as a diff.
- This is the direct answer to *"nested system of terms was generated by LLMs — not composed
  manually"*: nothing in the current build is LLM-derived. Every term was placed by explicit list
  membership (`heslar:*` 1266 terms, `teater:*` 4109 terms); the keyword matcher and the
  cross-source rescue never fired, and the LLM fallback stays opt-in and last.

### C — Settle the `Other` question (a decision, not a code change)
- Mechanically it is now one flag: `"Other": {"in_prompt": false}` in `taxonomy_config.json`.
  Default unchanged, so nothing moves until someone decides.
- Two facts worth having in that conversation:
  - With `heslar_map` in force the residue bucket is **empty** (`Other` = 0 across all three
    builds). "Should `Other` be excluded?" mostly dissolves — the terms it held now have real
    themes. What remains is the *separate* question of what a line with no interesting term
    should get, for which `Nerelevantní (meta-text)` already exists.
  - Excluding `Other` never closed the hole it was blamed for: `Rumunsko` (Chronology), `Malta`
    (Find Types), `Tuvalu` (Site Types) and `Kostarika` (Find Types) all reach today's prompt via
    keyword collisions on `roman` / `val` / `kost`. Excluding by `nazev_heslare` (`zeme`, `jazyk`,
    `dokument_licence`, `dokument_format`, `dohlednost`, `pocasi` → 310 AMCR terms) is what
    actually removes them.

### D — Define what "verified" means, then verify
This is @david-spacil's question 3 and the only one the repo has not moved on.
1. **Gold-label rules, written down before annotation**: are form labels (`OBEC`, `Druh nálezu`)
   meta-text? Is a less specific but correct term (`hrob` when `pohřeb kostrový` exists) wrong, or
   partially credited? Are `extracted_keywords_cs/en` scored, or only `teater_category`?
2. **Paradata beside every output set.** `atrium_paradata.py` already writes run records; the
   eight sample sets shipped without them, which is why the commit behind each is unknowable.
   Requiring the sidecar makes "do these come from the same commit?" answerable by looking.
3. **Sample size.** ~14 cited lines of 618 × 8 is anecdote-adjacent; the same verdicts flip on
   line choice (`qwen3_14b` on the second "Druh nálezu", `CTX196006127_1_25`). Fix the sample,
   score every line in it, publish per-model confusion against the gold labels.
4. Only then re-open the ranking — including the deferred large-MoE run, which is cheap to
   schedule once the harness produces comparable numbers.

### E — Keep the prompt/schema contract stable while the vocabulary moves
- `Nerelevantní (meta-text)` stays injected at index 0 and survives truncation.
- Temperature 0; most-specific-term preference (`zlomek keramiky` > `keramika`) stays in the
  system prompt, documented as contract so a model swap cannot silently drop it.
- Prefer **specificity + conservatism** over raw confidence — the bake-off showed 1.0 confidences
  on the worst over-generalisers.
- Theme order in the nested file is priority-descending and **load-bearing**: `build_system_prompt`
  truncates a prefix, so re-sorting the file changes which themes survive a tight budget. Do not
  "tidy" it with `sort_keys`.

## Verification / done-criteria
- `VOCAB_PATH` resolves to the adopted artifact and a run's paradata records which one.
- `python3 vocab_build.py --from-flat --check` exits 0 on a clean tree (nesting reproducible from
  the committed flat files alone).
- `heslar_map` / `teater_branch_map` carry a domain sign-off, with corrections landing in config
  rather than in generated files.
- The `Other` policy is recorded as a decision in the thread, whatever it is.
- A written scoring rubric + one fully-annotated sample exist; model scores are recomputed against
  the adopted vocabulary and are reproducible from paradata.

## Known adjacent breakage (flagged, not part of this issue)
- `llm_config.txt:66` sets `INPUT_DIR=data_samples/DOC_LINE_LANG_CLASS`, which does not exist —
  the real directory is `DOC_LINE_CATEG`. Blocks a true end-to-end run out of the box.
- `vocab_manager.py` and `tests/test_vocab_manager.py` are byte-identical in `atrium-llm-enrich`
  and are **not** in the hub's `docs/templates/shared/`, so they drift with no CI guard. The
  vocabulary refresh needs mirroring there (its `llm_client_shared.py` carries the same
  hard-coded `Other` exclusion and the same dead `other_cap` tail), and a `SHARED_FILES` row
  would stop the next divergence.
