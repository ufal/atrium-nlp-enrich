## 0. Governing principles

Everything below is subordinate to three rulings. When a task here conflicts with one of them, the ruling wins.

**P1 — Apply, don't reorganise.** AMCR and TEATER remain authoritative in how their terms are organised and interpreted. Nothing in this workstream constitutes a change to either source vocabulary. Any actual change to AMCR needs a dedicated decision process outside this issue.

**P2 — Facets are plumbing.** They organise and prioritise the prompt. They are not semantic output and not a new taxonomy. Keep "which terms are available to the model" strictly separate from "how those terms are grouped for inference" — including in how the code, the config, and the output schema are structured.

**P3 — Keep by default; exclude on evidence.** A TEATER branch comes out only when enrichment results show it is irrelevant or introduces systematic, otherwise unsolvable noise. Purely technical/administrative AMCR lists are the standing exception.

**Goal:** the offered vocabulary is "everything from both sources except lists that are technical or administrative rather than semantic."

### A1 — Reinstate the TEATER branches (P3)

| Branch | Label                                    |     Terms | Target facet                |

**A1a — resolve O4 before running the build.** Reinstating 2900 (historical regions and state formations), 3076 (dynasties), 2558/3091 (battles and wars) puts place and people names back into the offered enum, which contradicts the standing system-prompt rule that a country or regional name must never be selected as the primary category. This is the exact failure mode (`Dánsko`, `Zimbabwe`, `Východní Timor`) the thread fought from April to July. Three options, in order of preference:

1. **Reinstate and relax the guardrail** — replace the absolute prohibition with a preference ("select a geographic, ethnic or dynastic term only when the line is genuinely about it; prefer an archaeological content term otherwise"), then let D/E measure whether it holds. This is what P3 implies: exclusion by evidence, not by assumption.
2. Reinstate `etnika` (2560) only, keep the geographic and dynastic sub-branches out pending evidence. Defensible under P3 as "systematic, otherwise unsolvable noise", but the evidence has not been gathered against the current prompt.
3. Reinstate everything and leave the guardrail as-is — **do not do this.** The prompt would forbid what the vocabulary offers, and the resulting scores would measure the contradiction rather than the model.

*Recommendation: option 1, with the geographic-guardrail behaviour called out explicitly as a metric in D so option 2 stays available on evidence.*

## 3. Workstream B — Dedup and term identity

This is where most of the actual code work sits. Four independent defects, one ordering constraint between them.

### B1 — Key dedup on `cs` + `en`, not `cs` alone (finding 1)

Covers 15 of the 31 contested labels, including `zámek` (lock vs. château), `portál`, `kůl`. Does **not** cover the other 16, where the strings are identical in both languages and only the role differs (`budova`: AMCR `nalezove_okolnosti` "found in a building" vs. TEATER "a feature type") — those need B4.

Note the within-source scale: AMCR alone registers `kostel` twice (HES-000021 `areal`, HES-000465 `objekt_druh`) and 194 of 1460 AMCR records are dropped by first-occurrence-wins. B1 recovers those.

### B2 — Carry all discarded ids on the surviving term (M7)

- **Vocabulary file:** each term gains the full set of source records it absorbed — `{source, id, scheme, cs, en}` per record. 515 groups, 642 discarded records.
- **Prompt:** unchanged. Ids are not serialised into the system prompt.
- **Output:** after inference, attach the id set for the selected term to the enrichment record (e.g. `teater_category_ids`). Keep the existing `teater_category` string field untouched so nothing downstream breaks.
- **Reversibility:** M7 was given as "list them now and drop it if it will create some issues", so keep the emission behind a config key rather than hard-wiring it.

### B3 — Bracketed qualifiers for genuine homonyms (M8)

Two records sharing a string collapse into one enum entry — constrained decoding cannot offer two identical terms — so one meaning is currently unreachable. Follow the convention already used 319× across both sources (58 AMCR, 261 TEATER, e.g. `GPS (navigační systém)`).

- **Qualifier source:** the record's own sub-branch / heslář label → `zámek (stavební prvek)`, `zámek (sídlo elity)`.
- **Scope:** only where the records genuinely denote different things. 376 of 515 groups share an English gloss and need no qualifier — list the ids (B2) and move on. Of the 139 differing-gloss cases, most are translation variance (`pevnost` = *fortress* / *fort*); only real semantic splits get a bracket.
- **Prompt-only:** the bracketed form is what the model selects; post-inference, strip the qualifier for the emitted keyword and keep the disambiguation in the id set from B2. So the surfaced keyword stays `zámek` — with the correct id attached.
- **Review load:** 139 rows to read, of which @david-spacil has already covered 28.

### B4 — Per-term overrides — build `taxonomy_overrides.json` (O5, finding 4)

Placement is keyed by list and by branch only, so single terms cannot be moved. This is not optional any more: B3 requires per-term qualifiers, and the 16 role-differing collisions have no key that separates them. Minimum viable shape:

```jsonc
{
  "_comment": "Per-term corrections applied AFTER heslar_map / teater_branch_map. Each entry states a reason.",
  "overrides": [
    { "match": { "source": "amcr", "id": "HES-000817" },
      "facet": "Feature", "qualifier_cs": "stavební prvek", "reason": "…" }
  ]
}
```

Match on `(source, id)` — never on the bare label, which is exactly the ambiguity being fixed. `build_nested()` already validates that every map value is a declared facet or `__exclude__`; extend that validation to overrides, and record `placed_by = override:<id>` in the audit CSV so the traceability property holds.

### B5 — Apply exclusion *before* dedup (finding 3)

Currently a term whose winning record sits in an excluded list is dropped even when a kept list also claims it. Already lost: `úřední písemnost`, `olej`, `vodní pramen` (branch 288 claimed them first). `papír` would join them when `dokument_material` is excluded in A2 — so **B5 must land before or with A2**, or A2 silently deletes terms it has no business touching.

Fix: filter excluded records out of each source's record set first, then dedup across what survives. Add a regression test asserting those four terms are present after a build with 288 and `dokument_material` excluded.

### B6 — Ordering

```
B5 (exclusion before dedup)  ─┐
B1 (cs+en key)               ─┼─→ A5 rebuild ─→ B2 (ids) ─→ B3 (qualifiers, needs B4)
B4 (overrides mechanism)     ─┘
```

B5 and B1 change which records survive, so they must precede the A5 rebuild. B2 and B3 operate on the surviving groups.

## 4. Workstream C — Prompt and schema contract

**C1 — Resolve the geographic guardrail** per A1a. Whatever is chosen, write it into the system prompt as an explicit rule and into `6.plan.md` as contract, so a later model swap cannot silently drop it.

**C2 — Keep the invariants.** `Nerelevantní (meta-text)` at index 0 and truncation-proof. Temperature 0. Most-specific-term preference (`zlomek keramiky` > `keramika`, `pohřeb kostrový` > `hrob`). Static tiers first, `<target_line>` last, so the APC prefix hash stays intact. Facet order priority-descending — `build_system_prompt` truncates a *prefix*, so re-sorting the file changes what a tight budget keeps; do not "tidy" it with `sort_keys`.

**C3 — Verify the budget on the real build.** @david-spacil's estimate is ~57.9k system-prompt tokens, ~61k per request. Measure it on the actual A5 artifact with the production tokenizer and record the number in the run's paradata. Any registry model below ~128k context needs its surviving term count checked before its output is trusted — a truncated prefix fails silently.

**C4 — Output schema additions** from B2/B3: `teater_category_ids` (config-gated), and the keyword emitted with the bracketed qualifier stripped. Document both in the README's example output record.

## 5. Workstream D — Evaluation criteria *(critical path)*

Nothing downstream produces a trustworthy number until this exists. It is also the one item neither reviewer has moved on since 11 August.

**D1 — Write the gold-label rubric before annotating anything.** Answer, in the issue, so the answers are citable:
- Are form labels (`OBEC`, `ČÍSLO PARCELY`, `Druh nálezu`) meta-text? *(Proposed: yes — a field name is not content.)*
- Is a correct-but-less-specific term wrong, or partially credited? *(Proposed: partial credit, tracked separately, since the prompt actively instructs specificity — full-credit-only makes the metric insensitive to exactly the behaviour being asked for.)*
- Are `extracted_keywords_cs/en` scored, or only `teater_category`? *(Proposed: both, reported separately — the keyword array is what actually reaches an index.)*
- **New, from B3/F:** when two vocabulary entries are legitimately both correct for a line (`most` vs `most/brod`), both count as correct. This must be in the rubric before scoring, or the composite-label problem is scored as model error.
- **New, from A1a:** how a geographic/ethnic selection is scored, so the guardrail decision is measurable rather than assumed.

**D2 — Fix the sample.** ~14 cited lines out of 618 × 8 is anecdote-adjacent, and the verdicts demonstrably flip on line choice (`qwen3_14b` on the second "Druh nálezu", `CTX196006127_1_25`). Pick a fixed line set, score *every* line in it, publish per-model confusion against the gold labels.

**D3 — Paradata beside every output set.** `atrium_paradata.py` already writes run records; the eight shipped sets have none, which is why "do these come from the same commit?" was unanswerable. Make the sidecar mandatory, and include the vocabulary artifact's identity (path + `meta.json` sha) so a run is traceable to the exact term set it saw.

## 7. Workstream F — The open question we were handed

**F — Two different labels meaning the same thing.** `zámek/zámeček/vila` vs `zámek`, `most/brod` vs `most`, `budova/stavba`, `muzeum/skanzen` — 15 pairs where AMCR packs related concepts into one entry and a component also exists standalone, so the concept is offered twice, in two facets. @motyc: *"Not sure. Please try to come up with solution while looking into data."*

Proposed approach, to be validated against E3 rather than asserted:

1. **Keep both, link them.** Under P1, dropping an AMCR label is a change to AMCR's own content — precisely what the principle forbids. Instead add an equivalence relation (`same_as`, keyed on `(source, id)` pairs) in the vocabulary file, populated for the 15 pairs.
2. **Let the equivalence do the work at scoring time**, not at prompt time: both entries stay selectable, and D1 counts either as correct. This makes the ambiguity harmless where it actually causes damage — in the metric.
3. **Optionally prefer one at prompt time**, if E3 shows the duplication measurably splits model attention. That is an evidence-driven, reversible tuning decision rather than a vocabulary edit — consistent with P1 and P3.
4. Report the finding back to @motyc with E3's numbers attached, since he asked for a data-informed answer rather than a judgement call.
