## Context

A born-digital document has no ALTO, and flexiconv is off the production chain, so its TEITOK was text only. Its record already carries `pages[].canvas` and `lines[].bbox` in TEITOK's convention (top-left origin, y down) and reaches stage 4 as the run's baseline. The work is an adapter, not a second writer: the record is read into the structure `_parse_alto()` returns, and alignment, page resolution, the writer and the hook run unchanged. K4TEL added the record-alone input on 2026-10-15.

## Decisions (K4TEL, 2026-10-15)

1. Word boxes apportioned by character offset, declared approximate.
2. `pt` in `bbox_scale.unit_per_inch`; `IMAGE_DPI` and page images scale.
3. Page images named as for ALTO.
4. `/enrich` and `/jobs` take the record alone.

## As implemented

### Phase A — the adapter: `api_util/record_layout.py` (new; in `.github/production-image.json`)
- **`text_lines()`** is the one line selection for text and layout: `lines[]` with text, in record order, less `atrium_vocab.UNTRUSTWORTHY_LINE_CATEGORIES`. A page is numbered by its `page_index`.
- **`record_rows()`** gives the service's table: `page_num` is the index, `line_num` is 1-based per page.
- **`record_has_geometry()`**: a canvas page with a boxed line on it.
- **`word_boxes()`**: the share of the line box by character offset, along the longer side. A box more than 1.5 times taller than wide counts as vertical text.
- **`parse_record_layout()`** returns the 5-tuple:
  - pages per canvas, with a per-page `unit` (`px` → `pixel`);
  - strings per word, coordinate-free when the line or page has no geometry;
  - blocks per `group_id` and page, with `subtype = style.region`;
  - `meta`: `layout_source="record"`, `page_labels`, `page_count`, `orgfile`, `record_file`, and `converter` with its date (the first contributor that wrote `lines`).

### Phase B — the writer and the layout choice
- **`api_util/teitok_alto.py`:**
  - `_parse_alto()` sends a `.json` path to `parse_record_layout()`;
  - `_build_page_scale_map()` takes the page's own unit, words the tier-3 warning for a record, and rounds the tier-3 surface size instead of truncating it (A4 is 841.89 pt);
  - `_Coords.fmt_str()` parses floats;
  - `_header_xml()` has a record branch: `orgfile` = `source.filename`, `sourceDesc` names the record, the converter's `<application>`, `<change who="digital-convert" type="converted" when="{its date}">`, and "token boxes apportioned from line boxes (approximate)" in the writer's `desc`;
  - the `[layout]` log line covers records.
- **`api_util/doc_identity.py` `layout_source(..., record_dir=None)`:** ALTO, then the converted TEITOK, then the record with geometry. `summarize_nt_udp.py` passes `document_json_dir`.
- **`api_util/bbox_scale.py`:** `"pt": 72.0`.
- **`api_util/document_hook.py`:**
  - `entities[].page` and the `pages[]` merge are keyed by the record's label through `_page_keys()` (`page_index` → `page`);
  - a comment says the `lines[]` merge must never write `bbox` on a digital-born record.

### Phase C — the service and the spec
- **`service/api.py`:**
  - `/enrich` and `/jobs` take `file: File(None)`; `_read_text_input()` serves both;
  - without `file`, the rows are `record_rows(record)` and the `doc_id` is the record's;
  - refused with 422: no input at all, a record without text, and `alto` without a table;
  - `_FILE_HELP` and the `layout_source` description name the record.
- **`service/enrichment.py`:** `layout_kind()` takes the uploaded layout, else `"record"` when `record_has_geometry(document_json)`, else `"rows"`.
- **`service/openapi.json`** regenerated: three descriptions changed, and `required` dropped on the `/enrich` and `/jobs` bodies. `compare` reports `compatible`.

### Deviations from the 10-15 plan
- **No `IMAGE_DPI` in the service.** `tests/env_contract_data.py` keeps `IMAGE_DPI` a batch-pipeline knob, "not a deployment", and `config_api.txt` assigns it bare. The service answers in points and `/rescale` (`scale` = DPI/72) converts. A request field `image_dpi` would be the way in, if wanted.
- **No `is_record()` sniff:** a `.json` layout path is the record.
- **The hook test** lives in `tests/test_record_layout.py`, with the other #42 tests.
- **No separate 422 `reason`:** the record-alone refusals are plain 422s, like "No usable text rows".
- **No CONTRIBUTING row:** release rows come with the version bump. Suggested row:

  `| **v1.1.0-beta** | TEITOK layout from a born-digital record (#42): a <surface> per page from pages[].canvas, lines[].bbox on <lb>, token boxes shared out from them; layout_source "record"; /enrich and /jobs take the record alone (file optional). pt in bbox_scale (re-vendor into digital-convert). | Pre-release |`
