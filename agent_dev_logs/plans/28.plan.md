## Context
The issue asked for an XSD gate at the end of `api_4_stats.sh`, linked to "the official TEITOK schema", enforced in
CI. What shipped (v0.18.3) is sound engineering — lxml validator, pinned no-namespace XSD, hard stage-4 gate, advisory
`/rescale` verdict, a named CI workflow with a negative test and a real-writer round-trip — but one premise of the
issue does not hold: **there is no official TEITOK schema**. None of the TEITOK author's repositories (flexiconv,
flexipipe, xmltokenizer, flexicorp, teitok-tools) ships an XSD, RNG or DTD; TEITOK conventions live in their
readers/writers. The XSD was therefore authored *from our writer*, and the 2026-09-23 audit showed the consequence:
output that upstream tools misread (spacing, MWTs, NER types) passed the gate. The gate stays, and gained a second,
independent axis — **conformance to how upstream TEITOK tools read the file**.

## Strategic actions

### A — Upstream-conformance lane ✅ (branch)
1. `tests/test_teitok_conformance.py`, stdlib, always runs: generates TEITOK from a synthetic CoNLL-U + ALTO (MWT
   `abych`, `SpaceAfter=No` before punctuation, at an entity end and at the document end, a line break after a
   space, OntoNotes PERSON/GPE/DATE) and re-reads it **the way upstream does** — a space in `tok.tail` (flexiconv
   `load_teitok`), surface = `<tok>` text, `<dtok>` = words, `head` → `@id` → `@ord` — asserting equality with the
   input (sentence texts, every `SpaceAfter`, MWT words, heads, id patterns, entity attributes, header phases).
2. Same file: `flexiconv.io.teitok_xml.load_teitok` round-trip when flexiconv is installed (pinned `v0.3.10`).
3. `validate_teitok_xml.py --profile core` — used for flexiconv output instead of `--wellformed-only`.

### B — XSD moved with the writer ✅ (branch)
4. `teitok.xsd` as listed above; `schemas/teitok/README.md` with the format-2 table, *Upstream conformance* (pinned
   refs) and the regeneration procedure.
5. `data_samples/TEITOK/*` regenerated with the real writer (NameTag model as recorded in `data_samples/paradata`);
   fixtures `CTX_*` are real writer output; the legacy fixture keeps format-1 acceptance tested.

### C — Emitters separated ✅ (branch)
6. flexiconv output → `TEITOK_FLEXICONV_DIR` (default `$TEITOK_OUTPUT_DIR/flexiconv`), gated by `--profile core`;
   `api_4_stats.sh` passes `--exclude` for it.
7. Resume safety: writer stamp `<application ident="atrium-nlp-enrich" version="teitok-2">` + `REGENERATE_TEITOK=true`.
