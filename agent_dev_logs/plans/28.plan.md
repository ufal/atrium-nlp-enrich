# Strategy — Issue #28: Implement TEITOK XSD Schema-Conformance Gate

> Issue [\#28](https://github.com/ufal/atrium-nlp-enrich/issues/28) · Labels: `enhancement`, `development` · **Status: 🔍 Tocheck — gate landed in v0.18.3; the remaining work is turning a shape-stability check into a TEITOK-conformance check**
> _Refreshed 2026-09-23 (TEITOK/flexi* audit; umbrella plan [`../teitok_conformance_plan.md`](../teitok_conformance_plan.md), with [#9](9.plan.md) and [#10](10.plan.md)). Supersedes the 2026-08 plan (xmllint + `api_util/validate_teitok_xml.sh`), which was not the design that shipped._

## Context
The issue asked for an XSD gate at the end of `api_4_stats.sh`, linked to "the official TEITOK schema", enforced in
CI. What shipped (v0.18.3) is sound engineering — lxml validator, pinned no-namespace XSD, hard stage-4 gate, advisory
`/rescale` verdict, a named CI workflow with a negative test and a real-writer round-trip — but one premise of the
issue does not hold: **there is no official TEITOK schema**. None of the TEITOK author's repositories (flexiconv,
flexipipe, xmltokenizer, flexicorp, teitok-tools) ships an XSD, RNG or DTD; TEITOK conventions live in their
readers/writers. The XSD was therefore authored *from our writer*, and the 2026-09-23 audit showed the consequence:
output that upstream tools misread (spacing, MWTs, NER types) passes the gate. The gate must stay, and gain a second,
independent axis — **conformance to how upstream TEITOK tools read the file**.

## Strategic actions

### A — Upstream-conformance lane (new; the missing half of the gate)
1. `tests/test_teitok_conformance.py`, stdlib, always runs: generate TEITOK from `data_samples/UDP_NE/*` + ALTO and
   from synthetic CoNLL-U (MWT `abych`, `SpaceAfter=No` before punctuation and at a `<name>`/`<lb/>` boundary, an
   OntoNotes entity), then re-read it **the way upstream does** — spacing from the whitespace between `<tok>`s
   (flexipipe `_token_from_tok_elem`, flexiconv `load_teitok`, `teitok2conllu.pl`), surface = `<tok>` text,
   `<dtok>` = syntactic words, `head` → token `@id` — and assert equality with the input CoNLL-U (forms, `SpaceAfter`,
   heads, sentence count, entity spans).
2. Same file, `pytest.importorskip("flexiconv")`: `flexiconv.load_teitok` round-trip at the **pinned `v0.3.10`**
   (token count, forms, `space_after`, sentences). `teitok-schema.yml` installs `requirements_flexiconv.txt` for this
   step only.
3. `validate_teitok_xml.py --profile core`: TEITOK-core lint that holds for *any* TEITOK profile — `<TEI>` root,
   a `<text>`, unique non-empty `@id` on every `<tok>`/`<s>`, `head` references resolve, no whitespace between a
   `join="right"` token and its successor, non-negative integer bboxes. Used for flexiconv output instead of
   `--wellformed-only`.

### B — Move the XSD with the writer (same change set as the writer fixes, never separately)
4. `teitok.xsd`: mixed-content `tok` allowing `<dtok>` children; optional `ord`, `sameAs`, `onto`; `cnec` optional;
   non-negative `bboxType`; `notesStmt/note`, `profileDesc/langUsage`, `change@type/@subtype`, a writer version stamp in
   `appInfo`; TEITOK-native ids (`w-N`, `s-N`, `n-N`, `facs-N`, …) are plain strings — no pattern.
5. `schemas/teitok/README.md`: new *Upstream conformance* section naming the pinned upstream refs and what the lane
   checks; keep the "went wrong once" history.
6. Regenerate `data_samples/TEITOK/*.teitok.xml` **with the real writer** and keep `test_committed_data_samples_are_conformant`
   + a new "samples equal regenerated output" test so artefacts can no longer drift from code.

### C — Separate the emitters
7. flexiconv output → its own `TEITOK_FLEXICONV_DIR` (default `$TEITOK_OUTPUT_DIR/flexiconv`), gated by
   `--profile core` in `api_flexiconv.sh`; the stage-4 full-XSD gate excludes it (explicit `--exclude` or per-dir call).
8. Resume safety: `api_4_stats.sh` skips documents whose `.teitok.xml` exists; once the format changes, a writer
   version stamp + `REGENERATE_TEITOK=true` prevents mixed-format directories.
