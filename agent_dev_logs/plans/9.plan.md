## Context
TEITOK draws token highlights over the page image using each element's `bbox`, so the coordinates must live in the
image's pixel space. The pipeline gets there from ALTO via a 3-tier scale map (companion image → user DPI → 1.0) and
offers two after-the-fact tools (`POST /rescale`, `fix_teitok_bboxes.py`). The 2026-09-23 audit confirmed the scale
tiers work, but found that the writer also shifted every box by the ALTO PrintSpace origin while declaring the full
page in `<surface>` — a coordinate space nothing else in TEITOK or ATRIUM uses — and that the batch fixer could not run
at all. Upstream TEITOK converters (flexiconv `io/alto.py`, teitok-tools `page2teitok.pl`/`hocr2teitok.pl`) write
absolute page-origin pixels, and the relative-coordinates request (ufal/flexiconv#1) is unanswered.

## Strategic actions

### A — Make the post-factum tools work ✅ (branch)
1. `fix_teitok_bboxes.py`: `fix_name_close_tags()` / `detect_source_size()` unpacked correctly; `<surface>` rescaled
   only when it is the detected source; `[OK] file: N bbox value(s) rewritten`; exit 1 if any file failed.
2. `tests/test_fix_teitok_bboxes.py` (scale + surface, directory, `--dx/--dy` sign, `--unit mm10 --dpi 254`, `</n>`
   repair, missing path, CLI subprocess); `tests/test_cli_orchestration.py` (moved from `api_util/`).

### B — One coordinate space ✅ (branch; decided 2026-09-23: page origin by default)
3. `teitok_alto.py` `bbox_origin` (`page` | `printspace`), threaded `config_api.txt` `BBOX_ORIGIN` → `api_4_stats.sh`
   → `summarize_nt_udp.py --bbox-origin` → `write_teitok_merged` (unknown value = `ValueError` / argparse error).
   - `page`: `dx = dy = 0`; `<surface lrx/lry>` = image size (tier 1), Page × DPI scale (tier 2), or Page size.
   - `printspace`: PrintSpace origin subtracted; `<surface>` = PrintSpace size (× scale); tier-1 ratio against the
     PrintSpace; coordinates outside it clamped to 0 with a counted warning.
4. `document_hook.py`: `entities[].bbox` **stays in ALTO page units** (revised from the first draft of this plan): it
   is the unit alto-postprocess's `lines[].bbox` uses in the same record, and with the page-origin default and no
   scaling it equals the TEITOK boxes. The record does not state an origin (no schema field for it).
5. `schemas/teitok/teitok.xsd` `bboxType` → non-negative integers (with #28's schema change set).
6. `TestSpatialAlignment`: page-origin default, printspace (shift + surface), clamping, unknown origin.

### C — Evidence and docs
