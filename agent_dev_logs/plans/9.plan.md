# Strategy — Issue #9: TEITOK output: image files dependence handling

> Issue [\#9](https://github.com/ufal/atrium-nlp-enrich/issues/9) · Labels: `enhancement`, `development` · **Status: 🔍 Tocheck — calibration shipped (v0.13.0 / v0.15.0), XSD gate done via #28; coordinate origin, the post-factum fixer and tier-1 evidence still open**
> _Refreshed 2026-09-23 (TEITOK/flexi* audit). Umbrella plan: [`../teitok_conformance_plan.md`](../teitok_conformance_plan.md) — this issue owns its Stage 2 (fixer) and the bbox-origin part of Stage 3._

## Context
TEITOK draws token highlights over the page image using each element's `bbox`, so the coordinates must live in the
image's pixel space. The pipeline gets there from ALTO via a 3-tier scale map (companion image → user DPI → 1.0) and
offers two after-the-fact tools (`POST /rescale`, `fix_teitok_bboxes.py`). The 2026-09-23 audit confirmed the scale
tiers work, but found that the writer also shifts every box by the ALTO PrintSpace origin while declaring the full
page in `<surface>` — a coordinate space nothing else in TEITOK or ATRIUM uses — and that the batch fixer cannot run
at all. Upstream TEITOK converters (flexiconv `io/alto.py`, teitok-tools `page2teitok.pl`/`hocr2teitok.pl`) write
absolute page-origin pixels, and the relative-coordinates request (ufal/flexiconv#1) is unanswered.

## Strategic actions

### A — Make the post-factum tools work (Stage 2 of the umbrella plan)
1. `fix_teitok_bboxes.py`: `xml_text, _ = fix_name_close_tags(xml_text)`; `w, h, _kind = detect_source_size(xml_text)`;
   report per file (boxes rewritten, `</n>` repairs); non-zero exit if any file failed.
2. `tests/test_fix_teitok_bboxes.py`: single file and directory, a `</n>` document, `<surface>` extents rescaled,
   `--unit mm10 --dpi 72`, sign convention of `--dx/--dy` pinned. Move `api_util/test_cli_orchestration.py` to
   `tests/` so the CLI smoke tests are collected.

### B — One coordinate space (decided 2026-09-23: page origin by default)
3. `teitok_alto.py`: new `bbox_origin` (`page` default | `printspace`), threaded like `dpi`: `config_api.txt`
   `BBOX_ORIGIN="page"` → `api_4_stats.sh` → `summarize_nt_udp.py --bbox-origin` → `write_teitok_merged`.
   - `page`: `dx = dy = 0`; `<surface lrx/lry>` = image size (tier 1), `Page` size × DPI scale (tier 2), or `Page` size.
   - `printspace`: `dx, dy` = PrintSpace origin; `<surface lrx/lry>` = PrintSpace `WIDTH/HEIGHT` (× scale); tier-1
     ratio computed against PrintSpace size; boxes outside the print space clamped to 0 and counted in a warning.
4. `document_hook.py` takes the same scaled/shifted boxes from `parse_and_align_conllu()` so `entities[].bbox` and
   TEITOK agree; `pages[].canvas` states the origin.
5. `schemas/teitok/teitok.xsd` `bboxType` → non-negative integers (with #28's schema change set).
6. Update `TestSpatialAlignment`: `test_printspace_margins_are_subtracted` becomes two cases (default page origin
   = raw coords; `printspace` = shifted + PrintSpace-sized surface).

### C — Evidence and docs
7. Commit `data_samples/pages/CTX000000001-1.png` (small valid PNG, half the ALTO page size, stdlib-generated) and a
   test that derives `sx, sy` from the files and checks a known token bbox and the `<surface>` extent.
8. README "ALTO-to-TEITOK XML Generation and Coordinate Alignment" + `config_api.txt` Image-Options comment +
   `service/README.md`: document the origin knob, the three tiers, `{doc}-{N}.<ext>` naming, that `/enrich` is
   text-only and `/rescale` is the API's alignment tool; drop "raw ALTO pixel values".
9. Relative coordinates: leave the README "future direction" note, pointing at ufal/flexiconv#1.

  coordinate in either mode.
- `entities[].bbox` in the document record equals the union of the entity's token bboxes in the TEITOK file.
- `pytest tests/test_teitok_preservation.py tests/test_fix_teitok_bboxes.py tests/test_rescale.py tests/test_document_hook.py -q` green.
- Close #9 when A–C are on `test`; the relative-coordinates wish moves to flexiconv#1 / a new issue if the TEITOK team responds.
