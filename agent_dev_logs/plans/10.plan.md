## Context
Non-tabular documents are converted by flexiconv straight to TEITOK XML (replacing stages 2–4), and keyword
extraction / LLM enrichment read the resulting `.teitok.xml` through the stdlib `teitok_read`. The design (06-15, five
decisions) is implemented and the mocked tests pass. The first real conversions with the pinned flexiconv `v0.3.10`
(2026-09-23) show why "not tested in practice" mattered: flexiconv's TEITOK is **not sentence-segmented** — plain
formats give `<p>` text, layout formats (PAGE XML, hOCR, ALTO) give `<tok bbox>` inside `<div>`/`<lb/>` — and
`teitok_read` only understands `<s>`, so every converted document contributes **zero rows**. On top of that the adapter
calls a non-existent library function, triggers runtime `pip install`s, collides on shared stems, and writes into the
directory the stage-4 XSD gate owns.

## Strategic actions

### A — Make converted documents readable (decision 2026-09-23: reader fallback now)
1. `api_util/teitok_read.py` (becomes the single canonical copy; llm-enrich re-vendors it):
   - rows: `<s>` as today; **else** one row per `<lb/>`-delimited line when the document has `<lb>` (PAGE/hOCR/ALTO
     output), with the line's token texts joined by their inter-token whitespace; **else** one row per text block
     (`p`, `head`, `item`, `cell`, `l`, `u`, `ab`), whitespace-normalised; page number from `<pb>` in all modes.
   - tokens: spacing from the whitespace after `</tok>` **or** `join="right"`; `<dtok>` text ignored; for untokenized
     documents a whitespace split with empty `lemma`/`upos`.
   - robustness from the llm-enrich copy: `</n>` repair before parsing, non-numeric `pb@n` tolerated; keep nlp's
     `upos`-from-`@upos` fix (llm's copy still reads `pos`/`type`).
2. Fixtures captured from real `v0.3.10` output (txt, md, PAGE XML, hOCR) under `tests/fixtures/teitok/flexiconv/`
   with row/token expectations; keywords (`yake`) and `llm_utils.read_input_rows` tests on them. Keep the documented
   caveat: the legacy KER method needs lemmas, which flexiconv output does not have.

### B — Fix the adapter and the conversion step
3. `api_util/flexiconv_convert.py`: `from flexiconv.api import run_convert` → `run_convert(in, out, to_format="teitok",
   options={"force": force})`, check `result.success` / `result.error_message`; CLI fallback
   `flexiconv --no-auto-install [--force] -t teitok IN OUT` with `timeout`; one-line error, non-zero exit, no traceback.
4. Output layout: `TEITOK_FLEXICONV_DIR` (default `$TEITOK_OUTPUT_DIR/flexiconv`) so converted files never collide with
   or get gated as writer output; `<stem>.teitok.xml`, and `<stem>.<ext>.teitok.xml` when two inputs share a stem in
   one run; re-runs skip existing outputs unless `FLEXICONV_FORCE=true`.
5. `requirements_flexiconv.txt`: `flexiconv[docx,odt,md,pdf,rtf] @ git+https://github.com/ufal/flexiconv.git@v0.3.10`
   so no format depends on a runtime install; update the pin comment.
6. `config_api.txt`: `FLEXICONV_FORMATS` += `xml hocr` (flexiconv sniffs PAGE/ALTO/TEI/TEITOK by content), new
   `TEITOK_FLEXICONV_DIR`, `FLEXICONV_FORCE`; `api_flexiconv.sh`: per-file `atrium_paradata.py` ok/skip entries,
   gate with `validate_teitok_xml.py --profile core` (from #28) on its own directory.
7. `para_config.txt` (here and in llm-enrich): `flexiconv = GPL-3.0-or-later ; conditional ; flexiconv converter (api_flexiconv.sh)`.
8. Optional: `run_pipeline.py --with-flexiconv` (off by default) runs the conversion before keywords/LLM; point
   `keywords.py -i` / `llm_config.txt INPUT_DIR` at `TEITOK_FLEXICONV_DIR` in the docs.

### C — Real-document experiment (the 08-02 task; close-out gate)
9. Inputs: flexiconv's own `examples/pagexml/aletheiaexamplepage.xml`, `examples/hocr/output_page_1.hocr`,
   `examples/alto/sample.alto.xml`, a docx and a txt/md, plus ≥1 real ATRIUM document per format when available.
10. Run `bash api_flexiconv.sh` → `keywords.py -i "$TEITOK_FLEXICONV_DIR" -m yake` → `llm_run.py` (remote backend or a
    dry run) and record per format: conversion ok, `--profile core` ok, rows/tokens read, keywords produced, bbox present
    (layout formats), text degradation observed.
11. Write the results into README "EXTRA: Converting Other Input Formats with flexiconv" (rewritten: real CLI
    `flexiconv [-f FMT] -t teitok IN OUT` / `-R`, `api_flexiconv.sh`, what flexiconv output contains, that it skips
    UDPipe/NameTag, the reader modes, the legacy-KER caveat, the licence).

### D — Later, opt-in (new issue, not part of #10)
12. Text-faithful linguistic annotation of flexiconv TEITOK: xmltokenizer (`profile="teitok"`, MIT) with UDPipe REST as
    `--backend-cmd` and NameTag on the same CoNLL-U → `<s>`/`<tok lemma upos …>`/`<name>` inside the converted file,
    gated by `FLEXICONV_ANNOTATE=true`. Alternative considered: flexiconv's own `--flexipipe` post-step (pulls
    flexipipe + its model downloads).
