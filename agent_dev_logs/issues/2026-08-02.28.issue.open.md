#### <img src="https://avatars.githubusercontent.com/u/65828620?u=80b39d3cb2967c52e1d4af28dcefc7a1efdfdc79&v=4" width="50">[K4TEL](https://github.com/K4TEL) opened issue at [2026-08-02 10:02](https://github.com/ufal/atrium-nlp-enrich/issues/28):

While `atrium-translator` rigorously validates its output against the AMCR XSD, the `nlp-enrich` module currently has no equivalent validation gate for its generated TEITOK XML. A strict schema-conformance check must be implemented at the end of the `api_4_stats.sh` script to catch malformed XML before it propagates to downstream consumers or is packaged into the LINDAT dataset release.

## Context & Rationale
* Invalid TEITOK XML causes silent failures in downstream visualizers and search indexes. Catching schema violations at the point of generation prevents poisoned data from entering the FAIR dataset.

## Tasks
- [x] Introduce an XSD validation step at the tail end of the TEITOK compilation process in `api_4_stats.sh`.
- [x] Link the validation to the official TEITOK schema definitions.
- [x] Update the CI pipeline to fail the build if the integration tests generate malformed TEITOK XML.

## Acceptance Criteria
- **Validation:** The pipeline formally rejects and logs an error for any document that fails XSD validation.
- **CI Enforcement:** GHA workflows successfully execute this validation step on the test fixtures.

#### By Sonnet Medium

**Update:** XSD validation gate for `.teitok.xml` is implemented and locally verified against the real writer (`api_util/teitok_alto.py::write_teitok_merged`)

- `schemas/teitok/teitok.xsd` — hand-authored from the writer's actual output (namespaced TEI, `xml:lang`), covering both the bbox/facsimile path and the no-ALTO text-only fallback. Provenance documented in `schemas/teitok/README.md`.
- `schemas/teitok/xml.xsd` — vendored locally so validation is network-free.
- `api_util/validate_teitok_xml.py` — lxml-based validator, `rglob("*.teitok.xml")` (flat or nested), `[OK]`/`[FAIL]` + diagnostics per file, exit 0/1. Matches the call already wired into `api_4_stats.sh`.
- `tests/test_validate_teitok_xml.py` — 9 tests, passing (valid / invalid / no-ALTO / nested / empty / missing dir).
- Fixtures: `CTX_valid`, `CTX_no_alto` (genuine fallback-path output), `CTX_invalid` (rejected by both lxml and `xmllint`, same diagnostic).

Cross-checked with `xmllint --noout --schema` independently of the Python validator — same pass/fail results on all three fixtures.

Next: wire CI step per the plan (install `libxml2-utils` or just rely on `lxml`, which is already a dependency — no new system package needed if we skip xmllint in CI).
