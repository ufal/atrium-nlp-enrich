# [\#41 Issue](https://github.com/ufal/atrium-nlp-enrich/issues/41) `open`: A LINDAT timeout or outage is reported as an empty run
**Labels**: `bug`, `development`, `integration`


#### <img src="https://avatars.githubusercontent.com/u/65828620?u=80b39d3cb2967c52e1d4af28dcefc7a1efdfdc79&v=4" width="50">[K4TEL](https://github.com/K4TEL) opened issue at [2026-10-08 12:18](https://github.com/ufal/atrium-nlp-enrich/issues/41):

When UDPipe or NameTag does not answer after the retries (timeout, 5xx, no connection), `call_udpipe.py` and `call_nametag.py` exit 1. The service maps exit 1 to 502 `Pipeline produced no output (empty run, exit 1).`; the cause (`UDPipe API failed permanently on chunk 1: …`) appears only in the log tail after it. An input that really yields nothing (`--strict-empty`) also exits 1, so status and first line cannot tell the two apart.

For a client this matters twice: the contract says to retry a 502 three times with backoff, which is right for an outage and wrong for an empty input; and a timeout, which the contract gives as 504 `limit_exceeded`, arrives as the same 502.

**Proposal:** a distinct exit code for "upstream did not answer" and one for its timeout, mapped to a detail naming the service and the error (`LINDAT UDPipe did not answer: …`), 502 or 504; exit 1 stays the empty run. Tested with a stub LINDAT that times out and one that returns 503.
