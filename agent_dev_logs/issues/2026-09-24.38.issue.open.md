#### <img src="https://avatars.githubusercontent.com/u/65828620?u=80b39d3cb2967c52e1d4af28dcefc7a1efdfdc79&v=4" width="50">[K4TEL](https://github.com/K4TEL) opened issue at [2026-09-24 08:25](https://github.com/ufal/atrium-nlp-enrich/issues/38):

Follow-up of #10 (action D). Documents converted by flexiconv (`api_flexiconv.sh`) used to end as bare TEITOK: no sentences, lemmas, POS, entities or ids. So the document record, NER, legacy KER keywords and the TEITOK format-2 guarantees covered only ALTO/table inputs.

**Design (implemented on 2026-09-24)** — this repo's own stages, not xmltokenizer/flexipipe: one writer, one id scheme, no new dependency, offline CI. The converted file is an intermediate.
- **Stage 1**: `build_manifest_row.py` reads the file's `teitok_read` rows. A table with the same `doc_id` wins; alto-postprocess #31's `--method text-lines` writes `DOC_LINE_CATEG/<doc>.csv` for the same inputs.
- **Stages 2–3**: unchanged (UDPipe, NameTag).
- **Stage 4**: `summarize_nt_udp.layout_source()` picks the ALTO, else the converted file, matched by `canonical_doc_id`. `api_util/teitok_layout.py` reads it into the ALTO parser's structures:
  - pages ← `<pb facs>`;
  - lines ← `<lb bbox>`;
  - words ← `<tok bbox>`, or block words without coordinates;
  - blocks ← element name as `subtype`.

  The writer produces format 2 under the full XSD; the header names flexiconv and the original document.
- **Switch**: `FLEXICONV_ANNOTATE=true`, or `run_pipeline.py --with-flexiconv`.

**Evidence (offline)**:
- `tests/test_teitok_layout.py`, `tests/test_flexiconv_annotate.py`;
- a real `api_1_manifest.sh` → `api_4_stats.sh` run on PAGE XML / hOCR / txt conversions: 3/3 pass the XSD gate and the core profile;
- the records validate against the schema (e.g. `Praze` → `LOC`/`GPE`, bbox `620 100 820 150`, `teitok_ref` `n-1`, `teitok_surface` `facs-1`);
- flexiconv v0.3.10 reads every output back.

**Open**
- [ ] live run with UDPipe/NameTag on real converted documents
- [x] service parity: document upload → annotated TEITOK in `/enrich` or `/convert` (after the flexiconv GPL decision)
- [x] page breaks for table inputs without layout (`# page_break = true` has consumers, no producer)
- [ ] optional: benchmark flexipipe/xmltokenizer annotation against this chain

Not released yet; `CONTRIBUTING.md` suggests v0.22.0.

**Added this round**
- The writer warns on stderr when `INPUT_PAGES_DIR` has no `<doc>-<N>.<ext>` for a page, when an image's pixel size cannot be read, and when ALTO units are not pixels and nothing scales them. Output is unchanged.
- README § "TEITOK XML" now covers the standards the format builds on, how a file is composed from the line table, UDPipe, NameTag and the layout, the tools that write or read TEITOK (with licences), and 14 pitfalls that produce a valid but misaligned file.

**Before reusing older TEITOK files:** files written by v0.21.0 or earlier start a new "page" at every UDPipe chunk, and they carry the same `teitok-2` stamp. Only their `<change type="converted" when="…">` date tells them apart. Regenerate them (migration note in `CONTRIBUTING.md`).

**Next:** tag v0.22.0 and re-run the E2E on its image; the live LINDAT run with the OntoNotes refresh of `data_samples`; report the two upstream reader bugs (flexipipe's document-global `@head`, flexiconv dropping `<dtok>`).
