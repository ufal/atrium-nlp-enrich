## 🎯 Goal

A client can tell, from the status code and the error body alone:

1. **The upstream did not answer.** LINDAT UDPipe or NameTag returned 5xx after the retries, or refused the connection. This should be a 502 whose detail names the service and the error.
2. **The upstream timed out.** This should be a 504 `limit_exceeded` naming the timeout setting, as the shared contract describes.
3. **The input yielded nothing.** This stays the 502 "empty run" it is today.

Today all three arrive as the same 502 with the same first line.

## 🔎 What the code does today (`86b0277`)

The chain from a dead LINDAT endpoint to the HTTP answer:

What the contract promises (shared `service/atrium_service.py:695-697`, mirrored in `service/openapi.json`):
- **502:** "An upstream service failed. Retry three times with backoff."
- **504:** "A time limit that depends on an upstream service expired (`reason: limit_exceeded`). Retry with backoff."

`limit_exceeded` may be sent with 504 (`REASON_STATUSES`, `atrium_service.py:227-234`; `atrium_limits.LIMIT_STATUSES = (413, 422, 504)`).

So:
- **An empty input** is told to retry three times, which is pointless.
- **A LINDAT timeout** (the per-request `TIMEOUT`, retried five times) never becomes the 504 the contract describes.
- **An outage and an empty input** cannot be told apart, because both read "empty run".

The only 504 today is `API_JOB_TIMEOUT` (`service/api.py:781`).

Existing tests:
- `tests/test_api_service.py:81-96` asserts that exit codes 1 and 2 map to 502 with "exit" in the detail; its `_make_stub` (`:241-259`) fakes `PipelineError`.
- `tests/test_backing_service_urls.py` drives `call_udpipe.main()` / `call_nametag.main()` against `http://127.0.0.1:99xx` stub URLs.
- No test makes LINDAT time out or answer 5xx.

## 🔑 Decisions open

1. **Exit codes.** Codes 1, 2 and 5 are taken.

   Proposal: `3` = the upstream did not answer (5xx after retries, connection refused or reset), `4` = the upstream timed out. The stage scripts propagate the client's code instead of `exit 1`.

   The runner already returns a stage's code unchanged, so the codes travel without further change.
2. **The reason code.** None is needed. 502 carries `reason: null` today, and a new registry code would mean a change to the hub-shared `atrium_service.py` plus six revendors. The detail names the service (`LINDAT UDPipe did not answer: <error>`). The 504 uses the existing `limit_exceeded` with `limit: lindat_timeout_s`.

## ✅ Done when

- **Stub LINDAT that times out:** `/enrich` answers 504 `limit_exceeded`, `limit: lindat_timeout_s`.
- **Stub that answers 503:** 502 with a detail that starts `LINDAT UDPipe did not answer` (or `LINDAT NameTag …`).
- **Empty input:** still the 502 "empty run".
- `service/README.md`'s exit-code map and error table say so.
- `tests/test_api_service.py`'s exit-code test covers 3 and 4.
