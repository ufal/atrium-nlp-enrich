## 🎯 Goal
Make TEITOK `bbox` coordinates line up with the page image shown behind the text, whether or not that image is on
disk: from a companion image, from a user DPI + ALTO `MeasurementUnit`, or from ALTO alone; and fix already-generated
files after the fact. Long-term wish (06-15): resolution-independent (relative) coordinates, pending the TEITOK team.

## 🧭 Architecture (as built, branch)
1. **3-tier scale map** — `api_util/teitok_alto.py::_build_page_scale_map` per page: (1) companion image
   `{doc}-{N}.{png,jpg,jpeg,tif,tiff}` in `INPUT_PAGES_DIR` (or next to the ALTO) → `sx = img_w / reference width`;
   (2) `IMAGE_DPI`/`ALTO_DPI` + `MeasurementUnit` (`inch1200`, `mm10`, `pixel`) → `bbox_scale.dpi_scale`;
   (3) fallback `1.0`. The located image's real extension is used in `<graphic url>`/`<pb facs>`.
2. **Origin** — `bbox_origin="page"` (default, `BBOX_ORIGIN` in `config_api.txt`): ALTO coordinates as they are,
   reference extent = ALTO Page, `<surface lrx lry>` = page (× scale). `bbox_origin="printspace"`: coordinates minus
   the PrintSpace origin, reference extent = PrintSpace (tier 1 divides by the PrintSpace width), `<surface>` =
   PrintSpace (× scale), margin content clamped to 0 and counted. `appInfo` records the origin
   (`<desc>bbox origin: page</desc>`).
3. **Shared primitives** — `api_util/bbox_scale.py` (`dpi_scale`, `scale_bbox_coords`, `BBOX_RE`/`SURFACE_RE`,
   `fix_name_close_tags`, `detect_source_size`) used by the writer, `service/rescale.py` (`POST /rescale`) and
   `fix_teitok_bboxes.py`.
4. **Plumbing** — `config_api.txt` (`INPUT_PAGES_DIR`, `IMAGE_DPI`, `ALTO_DPI`, `BBOX_ORIGIN`) → `api_4_stats.sh`
   → `summarize_nt_udp.py --pages-dir/--dpi/--alto-dpi/--bbox-origin` → `write_teitok_merged`. `/enrich` is text-only
   by design (workspace config blanks ALTO/pages); image alignment in the API is `POST /rescale`.
