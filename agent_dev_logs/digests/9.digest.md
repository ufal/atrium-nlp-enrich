## 🎯 Goal
Make TEITOK `bbox` coordinates line up with the page image shown behind the text, whether or not that image is on
disk: from a companion image, from a user DPI + ALTO `MeasurementUnit`, or from ALTO alone; and fix already-generated
files after the fact. Long-term wish (06-15): resolution-independent (relative) coordinates, pending the TEITOK team.

## 🧭 Architecture (as built)
1. **3-tier scale map** — `api_util/teitok_alto.py::_build_page_scale_map` per page: (1) companion image
   `{doc}-{N}.{png,jpg,jpeg,tif,tiff}` in `INPUT_PAGES_DIR` (or next to the ALTO) → `sx = img_w / Page@WIDTH`;
   (2) `IMAGE_DPI`/`ALTO_DPI` + `MeasurementUnit` (`inch1200`, `mm10`, `pixel`) → `bbox_scale.dpi_scale`;
   (3) fallback `1.0`. The located image's real extension is used in `<graphic url>`/`<pb facs>`.
2. **Origin shift** — every coordinate is written as `round((c − PrintSpace@HPOS/VPOS) · s)` (`dx, dy`), on the
   README's rationale that published images are cropped to the print space.
3. **Shared primitives** — `api_util/bbox_scale.py` (`dpi_scale`, `scale_bbox_coords`, `BBOX_RE`/`SURFACE_RE`,
   `fix_name_close_tags`, `detect_source_size`) used by the writer, `service/rescale.py` (`POST /rescale`) and
   `fix_teitok_bboxes.py`.
4. **Plumbing** — `config_api.txt` (`INPUT_PAGES_DIR`, `IMAGE_DPI`, `ALTO_DPI`, one definition each) →
   `api_4_stats.sh` → `summarize_nt_udp.py --pages-dir/--dpi/--alto-dpi` (`_float_or_none` for empty strings) →
   `write_teitok_merged`. `/enrich` is text-only by design (workspace config blanks ALTO/pages); image alignment in
   the API is `POST /rescale`.

## ✅ What's settled

- `.png` hard-coding removed; duplicate `INPUT_PAGES_DIR` removed from `config_api.txt`.
- `POST /rescale` works (regex transform, `</n>` repair, advisory `schema_valid`), covered by `tests/test_rescale.py`.
- XSD gate at the end of `api_4_stats.sh` — done under #28.

  `page2teitok.pl`, `hocr2teitok.pl`) all write **absolute page-image pixels, page origin**; ufal/flexiconv#1

  TEITOK convention today.

## ⚠️ Found by the 2026-09-23 audit
- **Origin inconsistency (writer)** — bboxes are PrintSpace-relative but `<surface lrx/lry>` is the full Page size
  (sample: block `220 160 …` written as `20 10 …` on a `1654×2339` surface). If the image really were cropped,
  tier 1 would have to divide by PrintSpace width, not Page width, so the code contradicts its own rationale. Real
  ABBYY fixtures shift by 30/6 px, the synthetic ones by 200/150. `api_util/document_hook.py` writes **unshifted**
  ALTO boxes into `entities[].bbox`, so TEITOK and the `atrium_document` record already disagree. The XSD accepts
  negative coordinates, which only this shift can produce. README/config still say an empty `INPUT_PAGES_DIR` writes
  "raw ALTO pixel values".
- **`fix_teitok_bboxes.py` is broken** — `fix_name_close_tags()` returns `(text, count)` and `detect_source_size()`
  returns `(w, h, kind)`, both unpacked wrongly → `TypeError` on the first file (reproduced). Its only test
  (`api_util/test_cli_orchestration.py`, no-args exit code) sits outside `pytest.ini` `testpaths`, so it never runs.
- **Tier 1 untested on real data** — the committed `data_samples/pages/` image planned in June was never added;
  `tests/test_teitok_integraion.py` (sic) writes a 1×1 PNG into `tmp_path` and only checks it exists.
- **Stale samples** — `data_samples/TEITOK/*` are unshifted and `xmlns=`-namespaced, i.e. not today's writer output.
