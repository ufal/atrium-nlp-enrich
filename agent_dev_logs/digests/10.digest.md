## 🎯 Goal
Accept any flexiconv-supported, text-containing format (pdf, docx, odt, rtf, html, md, txt, epub, tei, conllu, …;
PAGE XML and hOCR per the 08-02 task) as raw input, converted **to TEITOK XML**, while CSV/XLSX keep stages 1–4
unchanged. Agreed at the meeting: about inputs, not about post-processing outputs.

## 🧭 Architecture (as built)
1. **Conversion step** — `api_flexiconv.sh` (manual, not a `run_pipeline.py` stage, not reachable from the service)
   scans `INPUT_DOCS_DIR` for extensions in `FLEXICONV_FORMATS` and calls `api_util/flexiconv_convert.py` per file →
   `<stem>.teitok.xml` in `TEITOK_OUTPUT_DIR` (the same directory `api_4_stats.sh` writes and gates).
2. **Adapter** — `flexiconv_convert.py` tries `flexiconv.convert(…, target_format="teitok")`, falls back to the CLI
   `flexiconv -t teitok in out`, raises `FlexiconvNotInstalled` with an install hint when neither exists.
3. **Optional dependency** — `requirements_flexiconv.txt` pins `flexiconv @ git+…@v0.3.10` (`a982b88`), not in any
   Dockerfile; the tests skip the live cases when it is absent.
4. **Readers** — stdlib `api_util/teitok_read.py` (`read_teitok_rows/_text/_tokens`, `doc_id_from_path`);
   `keywords.py` and `llm_run.py` glob `*.teitok.xml` next to `.conllu`/`.csv`; `llm_utils.read_input_rows`
   synthesises `categ=""`, `quality_score=0.0` for TEITOK rows. Flexiconv output **replaces** stages 2–4 (no
   UDPipe/NameTag); keywords/LLM read it directly.
5. **Gate** — `api_flexiconv.sh` ends with `validate_teitok_xml.py --wellformed-only` (#28).

## ⚠️ Found by the 2026-09-23 real-document run
- **Zero rows for every format** — flexiconv's txt/md/docx/pdf/html/odt/rtf/epub output is untokenized (`<p>`/`<head>`
  text, no `<s>`/`<tok>`); its PAGE XML/hOCR/ALTO output has `<tok>` + `bbox` but **no `<s>`**. `read_teitok_rows()`
  only emits rows for `<s>`, so it returns `[]` for all of them (PAGE example: 532 tokens, 0 rows) → keywords and LLM
  get nothing. The "layout-free → one row per `<s>`" statement in the old digest was never true for flexiconv output.
- **The library path is dead code** — `flexiconv.convert()` does not exist (the programmatic API is
  `flexiconv.api.run_convert()`, which returns a `ConvertResult` instead of raising) → every conversion silently takes
  the CLI fallback; the mocked tests hide this.
- **Runtime installs** — the CLI auto-`pip install`s missing extras (`flexiconv[md]` observed) unless given
  `--no-auto-install`; the pin covers the core only, so docx/pdf/odt/md/rtf work today *because* of that install.
- **Name collisions and re-runs** — `x.txt` + `x.md` both map to `x.teitok.xml`; flexiconv refuses to overwrite, so
  the second file (and every re-run) fails with a `CalledProcessError` traceback; the shell loop reports "Skipping".
  A converted `CTX….pdf` would also collide with the writer's `CTX….teitok.xml`.
- **Shared directory vs. stage-4 gate** — flexiconv output lands in `$TEITOK_OUTPUT_DIR`, which `api_4_stats.sh`
  validates with the full writer XSD → a later `stats` run halts on any converted document.
- **Routing** — `FLEXICONV_FORMATS` has no `xml`/`hocr`, so the PAGE XML and hOCR inputs named in the 08-02 task never
  enter; flexiconv itself detects PAGE/ALTO/TEI/TEITOK by sniffing `.xml` content.
- **Docs** — the README "How to use flexiconv" recipe (`python flexiconv.py --input-dir … --output-fmt teitok`) does
  not match the tool (`flexiconv [-f FMT] -t teitok IN OUT`, `-R` for folders) and never mentions `api_flexiconv.sh`;
  it also says UDPipe/NameTag run on the converted files, contradicting decision 1. No flexiconv component in
  `para_config.txt`.
