## 1. The task in one paragraph

A locally-hosted LLM receives (a) a line of text from an OCR'd Czech archaeological report, (b) a controlled archaeological vocabulary, and (c) a rigid output template. It must return the vocabulary terms that actually describe that line, as schema-valid JSON. The original framing named the **TEATER** thesaurus as the vocabulary; in practice the pipeline was built against **AMCR**, and reconciling that discrepancy is what has occupied the thread since August.

The issue has two clearly separable halves:

- **The machine** — inference backend, constrained decoding, prompt construction, paradata. *Built, benchmarked, and largely settled since June.*
- **The vocabulary** — which controlled terms exist, how they are grouped, how duplicates are resolved, and how output is scored against them. *This is what still keeps #6 open.*

As of 4 September the vocabulary half is **decided**. Every ruling from the 24–27 August governance round is implemented and in force; the two questions that survived it — which excluded branches come back, and which same-label groups are genuine homonyms — were both answered on 4 September, each against a review artifact built for it. What remains is a build (a +2 638-term reinstatement, simulated and priced) and one thing nobody else can do for us: **the evaluation rubric**. The critical path has shifted entirely onto evaluation, and the corpus that blocked it in Phase 8 is present — though still untracked.

## 2. Chronology

### Phase 1 — Design and first implementation (17–29 April)

**17 Apr — issue opened** ([body](https://github.com/ufal/atrium-nlp-enrich/issues/6)). Requirement stated as: document + topic thesaurus + output template → filled template with related thesaurus terms.

**19 Apr — architecture survey** ([`4275635073`](https://github.com/ufal/atrium-nlp-enrich/issues/6#issuecomment-4275635073)). Comparison of Qwen 2.5 Instruct (7B/14B), Mistral NeMo 12B, Aya Expanse 8B, Bielik v2.3 11B, Llama 3.1 8B against Czech NLP competence and structured-JSON reliability. Two conclusions that survived everything after: **Qwen family as the baseline**, and **constrained decoding is non-negotiable** — prompt-engineered JSON is insufficient for an automated pipeline; token-logit masking must guarantee schema conformance. The initial proposal also included semantic-similarity retrieval of the top-N relevant thesaurus branches per chunk (later dropped) and ATRIUM paradata logging (kept).

**19 Apr — first draft** ([`4275706959`](https://github.com/ufal/atrium-nlp-enrich/issues/6#issuecomment-4275706959), commit `003c05b`). Ollama backend, `vocab_manager.py` harvesting from upstream APIs into a nested JSON taxonomy, `llm_pipeline.py` doing inference, `llm_config.txt` as the runtime config, output as `KW_PER_DOC/*_enriched.json`.

**22 Apr — engine shift** ([`4294672109`](https://github.com/ufal/atrium-nlp-enrich/issues/6#issuecomment-4294672109), commit `c9759a7`). Off Ollama, onto Hugging Face `transformers` + `lmformatenforcer` for token-level constraint. Semantic-embedding retrieval replaced by **thematic grouping plus binary-search token-budget truncation**. AMCR OAI-PMH harvesting implemented. Line-quality filtering and a ±2-line sliding context window added.

**22 Apr — first 6-model evaluation** ([`4295621515`](https://github.com/ufal/atrium-nlp-enrich/issues/6#issuecomment-4295621515), commit `b766d8c`). Qwen 2.5-14B AWQ best. Two failure modes named here that the thread has been fighting ever since:

- **"The Country Default"** — Bielik and Llama, faced with an uncategorisable line ("Obsah", "Literatura"), pick a country name (`Dánsko`, `Džibutsko`, `Finsko`) out of the `Other` bucket.
- **Over-generalisation** — Mistral NeMo tagging nearly every line `hradiště`, at confidence 1.0.

**23 Apr — mitigations** ([`4303604920`](https://github.com/ufal/atrium-nlp-enrich/issues/6#issuecomment-4303604920), commit `7e851e3`). Three fixes that are now contract:

- **`Nerelevantní (meta-text)` injected at index 0** and made truncation-proof.
- **`Other` capped to 15 terms** in the prompt builder.
- **Global document header** prepended to the context window so page 15 still knows the report's subject.

Vocabulary moved from flat to nested (`teater_nested_vocab.json`); `taxonomy_config.json` introduced with per-theme priorities. Result: Qwen and Mistral improved sharply; **Bielik collapsed** into a 20× `sídelní jeskyně` repetition loop, Aya ignored the constraints entirely.

**23–24 Apr — model array reshuffle** ([`4303610541`](https://github.com/ufal/atrium-nlp-enrich/issues/6#issuecomment-4303610541), [`4314234220`](https://github.com/ufal/atrium-nlp-enrich/issues/6#issuecomment-4314234220)). Sub-15B legacy models diagnosed as suffering attention dilution under the large injected taxonomy. Proposed triad: Ministral 3 14B / Qwen3 14B (non-thinking mode) / Bielik 11B v3. DeepSeek-R1-Distill explicitly disqualified — `<think>` traces collide with the logit enforcer.

**27 Apr — v0.9.2 review and hardening** ([`4326098887`](https://github.com/ufal/atrium-nlp-enrich/issues/6#issuecomment-4326098887), [`4326298781`](https://github.com/ufal/atrium-nlp-enrich/issues/6#issuecomment-4326298781), commit `89f3d82`). Prompt gains: OCR normalisation instructions, a **geographic guardrail** (never select a country or regional name as the primary category), two few-shot JSON examples, calibrated confidence ranges, and a preference for multi-word archaeological phrases. Post-inference guard forces `extracted_keywords = []` whenever the category is `Nerelevantní (meta-text)`.

**27 Apr — file restructure** ([`4326941406`](https://github.com/ufal/atrium-nlp-enrich/issues/6#issuecomment-4326941406), commit `fafbb37`, **tag v0.10.0**). Current shape: `llm_run.py` (entry point) → `llm_utils.py` (prompt composition, model registry, filtering, context window, inference loop) → `vocab_manager.py` (vocabulary + taxonomy).

### Phase 2 — vLLM migration and scale-out (29 April – 23 June)

**29 Apr — migration plan** ([`4341618772`](https://github.com/ufal/atrium-nlp-enrich/issues/6#issuecomment-4341618772)). Detailed rewrite spec: drop `transformers`/`bitsandbytes`/`lmformatenforcer` shims, move to `vllm.AsyncLLMEngine` with `tensor_parallel_size`, `enable_prefix_caching`, `guided_decoding_backend="xgrammar"`. Two design points with long-term consequences:

- **Remove vocabulary truncation entirely** — with 128k–262k windows the full vocabulary fits.
- **Invert the prompt structure** — static tiers (instructions → schema → vocabulary → few-shot) first, dynamic `<target_line>` last, so the APC hash chain isn't broken at token 0. Any dynamic content before the vocabulary block yields a 0% cache-hit rate on the ~20k-token prefix.

**20 May — implementation** ([`4496338006`](https://github.com/ufal/atrium-nlp-enrich/issues/6#issuecomment-4496338006), commit `3e24876`). `load_vllm_engine()` and `process_document_vllm()` land; `BACKEND=` config key routes between vLLM and transformers. Two bugs fixed: **silent mid-document abort** now writes a `<stem>_enriched.abort.json` sidecar, and **empty `categ` string** is now an explicit labelled skip. Five 70B–671B registry entries added (`qwen3-235b-a22b`, `deepseek-v3`, `llama4-maverick`, `llama3.1-70b`). `get_prompt_string()` memoised with `sort_keys=True` for a stable APC prefix.

**23 Jun** ([`4777800118`](https://github.com/ufal/atrium-nlp-enrich/issues/6#issuecomment-4777800118), commit `4ef89fc`). Cluster GPU drivers updated, unblocking vLLM 0.8+ and the larger models.

### Phase 4 — Verification stalls on an undefined target (11–18 August)

**11 Aug — @david-spacil's three blocking questions** ([`5253411317`](https://github.com/ufal/atrium-nlp-enrich/issues/6#issuecomment-5253411317)). This is the hinge of the whole thread.

1. **Which vocabulary are we actually mapping to?** `teater_nested_vocab.json` is 100% AMCR, harvested from `api.aiscr.cz/2.2/oai` `set=heslo` — 1267 terms, verified against a fresh harvest, all matching, nothing from TEATER. Only the filename and the `teater_category` field carry the TEATER name.
2. **Should `Other` stay excluded?** `build_system_prompt()` skips the entire `Other` group, so models see ~489 terms, not 1267. `Other` is not a curated group — it is the residue of the keyword matcher, and 228 of its terms have a proper home in TEATER's hierarchy (`most`, `menhir`, 21 archaeological cultures). Scoring against a withheld label conflates "model was wrong" with "label was never offered".
3. **What exactly is being verified?** The 25 May ranking reproduces in the data, but rests on ~14 cited lines out of 618 × 8 models, and flips on line choice — `qwen3_14b` fails on the second occurrence of "Druh nálezu" (`CTX196006127_1_25`) the same litmus test it passes on the cited one. No gold-label rules exist; no paradata accompanies the eight output sets, so their provenance commit is unknowable.

**18 Aug — the vocabulary adjustment** ([`5331394591`](https://github.com/ufal/atrium-nlp-enrich/issues/6#issuecomment-5331394591), commit `1493c28`). Three defects in `c8dc6de` fixed before adoption:

- **`Documentation` was 87% contamination** — 733 of 840 terms were TEATER branch `2557` (ethnic groups, historical regions, dynasties, battles: `Achaia`, `Afrika`, `Alpy`, `Anglie`, `Anglosasové`, `Aragonie`). New exclusions with stated reasons: `letiste`, `nalez_typ`, and the GIS/confidence/access-role enum columns. `teater_branch_map` now resolves most-specific-first, so branch `2557` is judged per sub-branch — `etnika` (2560) is one edit away from reinstatement. `VOCAB_PATH` repointed at `data_samples/vocab/union_nested.json` across both repos. Prompt 489 → 2172 terms.

| Sheet                                     | Content                                                                        | Scale     |

Outcome: the nine-facet structure holds (28 of 38 lists, 66 of 97 sub-branches, 20 of 31 contested labels confirmed). Corrections cluster in two places — **administration** (`muzeum` 32 terms and `památková péče` 21 sitting under *Metody zpracování*, proposed → `Location & Admin`) and **building vs. ground** (`kostel`, `kaple`, `mlýn`, `cesta` in `Activity Area`, proposed → `Feature`; `zahrada` the other way; `přírodní útvar` → `Finds Context`). Of 15 cross-source collisions, AMCR was the better record 9 times and TEATER 4 — "right more often than not, but not reliably enough to leave to a blanket rule."

Two questions routed to @motyc: the excluded branches (23 `deferred` rows, 2769 terms), and — created by the review itself — whether `Documentation` should dissolve, since excluding the 10 `dokument_*` lists drops it from 107 terms to 5.

**Four tooling findings routed to @K4TEL:**

1. **Dedup keys on the Czech label alone.** `zámek` is AMCR `predmet_druh` (*lock*) and TEATER 1439 (*châteaux*); the lock won, so the bare word now carries only that sense. `portál` and `kůl` are the same shape. Keying on `cs` + `en` covers 15 of the 31 contested labels. The other 16 are not homonyms — `budova` reads *building* in both records and only the **role** differs (AMCR `nalezove_okolnosti` = found in a building; TEATER = a feature type). No key separates those.
2. **The same concept also arrives under different strings.** AMCR packs related things into one entry — `zámek/zámeček/vila`, `most/brod`, `budova/stavba`, `muzeum/skanzen` — and where a component exists standalone, the concept is offered twice in two facets. This matters for scoring: `most` and `most/brod` are both reasonable answers to the same line. Unmeasurable on the current sample (only 2 of 15 pairs had both sides in the 489-term prompt; 10 had neither); becomes measurable on the first union re-run.
3. **Exclusion is applied after dedup rather than before.** A term whose winning list is excluded is dropped even when a kept list also claims it. `úřední písemnost`, `olej` and `vodní pramen` are already gone this way (branch 288 claimed them first); `papír` would join them if `dokument_material` goes.
4. **No per-term override mechanism exists.** Placement is keyed by list and by branch only. `taxonomy_overrides.json` is mentioned once, parenthetically, in `6.plan.md` — no file, no code, no other mention in the repo. This is why `zámek` and `budova` are marked `flag` rather than given a verdict.

### Phase 6 — Governance rulings (26–27 August)

**26 Aug — @motyc sets the frame** ([`5424905539`](https://github.com/ufal/atrium-nlp-enrich/issues/6#issuecomment-5424905539)). Verbatim substance:

> "In general, the source vocabularies should remain authoritative in how their terms are organised and interpreted. […] This task should be about applying the vocabularies, not reorganising them."

> "I am not sure how much the facet assigned to a particular term actually matters here. The main objective is to understand the semantics of the document and link it to the appropriate controlled term. If facets are primarily an internal mechanism for organising/prioritising the prompt, rather than part of the semantic output, I would distinguish clearly between **which terms are available to the model** and **how those terms are grouped for inference**. The latter should not be treated as a new authoritative taxonomy. If the full vocabulary fits into the model context, it may also be worth checking empirically how much facet placement affects the results at all."

> "Excluding parts of the TEATER vocabulary is possible, but I would not do so without a good reason. […] I would exclude branches primarily on the basis of evidence from the enrichment results — for example, if they prove irrelevant for the intended content description or introduce systematic and otherwise unsolvable bias/noise."

On AMCR he agrees that most of what is grouped under `Documentation` is purely technical or administrative and can be excluded; `udalost_typ` still seems useful; and if that leaves `Documentation` with one list, dissolve the facet and put `udalost_typ` wherever is practical, probably `Location & Admin` — "an implementation detail, rather than a semantic reclassification."

**26 Aug — clarification** ([`5426046951`](https://github.com/ufal/atrium-nlp-enrich/issues/6#issuecomment-5426046951)). @david-spacil clarifies the `kostel` complaint was never about redefining AMCR: **AMCR itself registers `kostel` twice** — [HES-000021](https://api.aiscr.cz/id/HES-000021) in `areal` and [HES-000465](https://api.aiscr.cz/id/HES-000465) in `objekt_druh`. Only the first occurrence survives; **194 of 1460 AMCR records are dropped this way.** He also flags that literal linking is currently impossible: even a perfectly correct `kostel` cannot resolve to one controlled term because it lives in three places. Context measurement: full AMCR + TEATER minus the technical lists = **4689 terms ≈ 57,900 tokens** of system prompt, ~61k per request with line context and reserved output, against 27,301 tokens then — roughly double, and every candidate model has 128k+.

**26 Aug — @motyc on dedup** ([`5426147439`](https://github.com/ufal/atrium-nlp-enrich/issues/6#issuecomment-5426147439)). Accepts the clarification. By "linking" he means using the term as a keyword — no direct link required. But: *"it would be not so difficult to keep the connection and list all related ids resulting from dedupe and it may open some better ways of usage… Consider it please."*

**26 Aug — the three dedup questions** ([`5427831261`](https://github.com/ufal/atrium-nlp-enrich/issues/6#issuecomment-5427831261)). Scope: **515 labels collide, 642 records discarded.** In 376 groups every record has the same English gloss (listing ids is obviously right). Most of the rest is translation variance (`pevnost` = *fortress* in AMCR, *fort* in TEATER). A few are genuinely two things: `zámek` has three records — HES-000817 and TEATER 2358 both mean a lock, TEATER 1439 a château; listing all three would assert an equivalence that is false. Proposed remedy is the convention both vocabularies already use — a bracketed qualifier, as in `GPS (navigační systém)`, of which there are already **319 instances (58 AMCR, 261 TEATER)** — giving `zámek (stavební prvek)` and `zámek (sídlo elity)`. The point is not facet marking: two records sharing a string collapse into one enum entry, so one meaning cannot be offered at all. Brackets could stay prompt-only, leaving the emitted keyword unaffected. Remaining work is bounded: of the 487 collisions not yet reviewed, 362 are identical in Czech and English; only **139 differing-gloss cases** need reading.

### Phase 7 — The settled decisions become code (3 September)

**3 Sep — decision recap and marching order** ([`5526554810`](https://github.com/ufal/atrium-nlp-enrich/issues/6#issuecomment-5526554810)). @K4TEL restates the Aug 24–27 rulings as a single checklist across the three areas (vocabulary creation, system prompt, JSON output) and sets the priority: *"Solve the obvious tasks before moving to the open-ended questions."* No new domain ruling — this comment is a scoping instruction. It also names the guardrail tension explicitly for the first time: the geographic rule "needs reconciling now that some TEATER branches with place/ethnic terms may be reinstated; **unresolved**."

**3 Sep — implementation** ([`5527223677`](https://github.com/ufal/atrium-nlp-enrich/issues/6#issuecomment-5527223677), commit [`a5e3c8a`](https://github.com/ufal/atrium-nlp-enrich/commit/a5e3c8a)). Every decided item lands; every undecided one is deliberately left alone.

*Scope (A).* The seven technical/administrative AMCR lists are excluded with a stated reason each — `dokument_typ`, `dokument_material`, `dokument_rada`, `dokument_ulozeni`, `dokument_zachovalost`, `dokument_nahrada`, `ext_zdroj_typ`. `udalost_typ` is kept and moves to `Location & Admin`; the `Documentation` facet is removed from the config entirely (M4/M5). The `muzeum` (TEATER 220) and `památková péče` (TEATER 253) sub-branches move out of `Methods` into `Location & Admin` via `teater_branch_map`, whose ancestor-chain resolution already reaches depth-2 nodes, so all descendants follow rather than only the two group headers (m2).

*Dedup and identity (B).* `vocab_sources.to_term_pairs()` was rewritten from "first record in canonical order wins, the rest vanish" to grouping every same-label record: the winner keeps the bare label and carries the others in a new `discarded_ids` field (M7). Exclusion moved **before** dedup (finding 3), which is what actually recovers `úřední písemnost`, `olej`, `vodní pramen` and — once `dokument_material` went — `papír`; each is now covered by a regression test naming the exact ids involved.

*Per-term overrides (B4, and the answer to O5).* `data_samples/taxonomy_overrides.json` now exists, matched on `(source, id)` and never on the bare label, applied ahead of `heslar_map`/`teater_branch_map` and recorded in the audit CSV as `override:<source>:<id>`.

*The conservative reading of M8.* A same-label group is treated as **one concept by default**; a record is only split into its own bracketed entry when an override explicitly says so. Deriving homonym-hood from a differing English gloss was considered and rejected against the data: `přírodní útvar` reads *natural landform* in AMCR and *natural feature* in TEATER, `cesta` is *roads* / *path/road* / *path* across its three records — all translation variance, and an automatic rule would have split every one of them. This keeps the differing-gloss review with @david-spacil (M10) rather than pre-empting it, and matches @motyc's own framing that most collisions are the same concept.

*Output (C).* `build_system_prompt()` additionally returns an id lookup and a qualifier strip map; `llm_run.main()` attaches `teater_category_ids` after inference and strips a bracketed qualifier back off `teater_category`, keyed by exact lookup so the 319 terms that legitimately contain parentheses (`GPS (navigační systém)`) are untouched. Behind `EMIT_CATEGORY_IDS` (default on), because M7 was granted as reversible.

**The gap `a5e3c8a` left.** The commit carried the code and the config but **not** the ten artifacts under `data_samples/vocab/`. For several hours `test` therefore held a `taxonomy_config.json` that dissolved `Documentation` next to a `union_nested.json` that still contained all 107 of its terms — and because `build_system_prompt` skips only what the config marks `in_prompt: false`, never a facet that is merely *absent*, every one of those terms still reached the prompt. `teater_category_ids` came out `[]` on every line for the same reason: stale entries carry no `source_id`. Nothing failed; the two halves simply disagreed and the stale half won.

### Phase 10 — v0.20.0, and both open questions answered (4 September)

**Morning — [`v0.20.0`](https://github.com/ufal/atrium-nlp-enrich/releases/tag/v0.20.0) ships.** The
vocabulary stops being something only its author can change: every decision in it
becomes a config edit. Ten `_settings` keys — `_exclusions[rule].status`,
`geo_guardrail`, `nested_keep`, `admin_stop_words`, `composite_separators`, plus
`tie_break`, both maps and both label tables — and five per-term override keys
(`facet`, `sub`, `qualifier_cs`, `same_as`, `same_as_suppress`). `validate_settings()` refuses an edit
that would silently do nothing — an undeclared facet, a relabel for an unmapped list, a
reason for something nobody excludes, an unknown override key, a stale `(source, id)`,
a pair both linked and suppressed — and reports every problem at once rather than one
per rebuild. `vocab_build.py` gains a gate that refuses to build a vocabulary
contradicting the prompt's geographic guardrail. Paradata finally records which
vocabulary build produced a run, and logs `amcr_vocab`/`teater_data` as the
CC BY-NC 4.0 components they are — `log_component` had never been called, so every
previous run under-reported its own licence.

**A sixth review sheet, and an uncomfortable number.** `vocab_review.py --specificity`
measures how often the vocabulary offers both a term and one of its own broader terms:
**914 of 1 297** offered TEATER terms — 70 % of the TEATER side, **44 % of the whole
vocabulary**. Every one of the 914 pairs is **intra-facet**, so scoring the facet
instead of the term separates nothing. Under strict exact match a model answering
`třetihory` where the gold label is `paleogén` scores what one answering `keramika`
scores: zero. This had been assumed a corner case; it is the largest single question in
the D1 rubric.

**[`5539299996`](https://github.com/ufal/atrium-nlp-enrich/issues/6#issuecomment-5539299996) — @motyc rules O3/O4.**
*"I prefer `Q1 - Reinstate them and relax the guardrail in the same change` +
`Q2 - bring back and evaluate later if problems raises` (i.e. same lens driving the
decisions)."* The parenthesis is the ruling: **P3 applies to both halves.** The
a-priori exclusions come back, and evidence — not anticipation — decides whether any of
them goes out again. The one outcome the decision package named as a trap (reinstate
while the guardrail still forbids) is declined explicitly.

**[`5541507280`](https://github.com/ufal/atrium-nlp-enrich/issues/6#issuecomment-5541507280) — @david-spacil agrees, and delivers.**
He endorses both calls and the replacement guardrail wording verbatim — *"select a
geographic, ethnic or dynastic term only when the line is genuinely about it; prefer an
archaeological content term otherwise"* — and returns the completed collision review:
**7 splits, 120 merges** across all 127 groups. He also asks a precise implementation
question about the qualifier convention.

**The answer to that question is yes.** Two records in one label group carrying the
*same* qualifier build the same `"{cs} ({qualifier})"` key; the second is appended to
the collisions warning list and skipped, so its id lands in **no** entry's
`discarded_ids` and survives nowhere in the vocabulary
(`vocab_sources.py:722-727`, reproduced directly). His convention — qualifier only on
the record that leaves the group — is correct, and it is currently enforced by nothing:
the drop is a warning line, not an error. That is an M7 violation waiting to happen and
is now a `validate_settings()` item.

**What the ruling costs, simulated rather than estimated.** Building the reinstated
config against the committed flat harvests: **2 074 → 4 712 terms (+2 638)**,
vocabulary-list prompt tokens **19 093 → 44 701 (+25 608)**, absorbed records
583 → 630, collision groups needing review 127 → **136 (+9)**. @david-spacil's own
context estimate from 26 August — *"~4 689 terms ≈ 57.9k tokens against 128k+
windows"* — was made for exactly this scope and lands within 0.5 % of the built result.

**Three regressions, and they are the familiar ones.** Reinstating TEATER 288 brings
back records that then win labels they previously lost, because `record_sort_key`
breaks ties on the lower id and branch 288's ids are low. `olej`, `vodní pramen` and
`úřední písemnost` — **precisely the terms the B5 exclusion-before-dedup fix rescued** —
move out of `Artefact`/`Feature` into the reinstated branch's facet. Nothing is lost
(M7 keeps every id), but a reviewed placement is silently undone. Three override lines
fix it; a test pinning all seven B5 terms stops it recurring on the next harvest.

**The guardrail pairing is enforced, not merely documented.** `geo_guardrail` declares
whether the clause is in force, how to recognise it, and which rules it reaches; the
build reads `llm_run.py` and fails on a mismatch. All four combinations were exercised:
only *(shipped config + old wording)* and *(reinstated config + new wording)* pass.
@motyc's "in the same change" is a mechanism.

**An honest correction to Phase 8's claim.** The collision sheet was ranked by gloss
dissimilarity on the argument that *"~30 rows carry the signal"*, with `zámek` at rank
10 offered as evidence the ranking worked. The returned verdicts say otherwise: the
seven splits sit at ranks **10, 45, 62, 66, 67, 97, 119** — only **1 of 7** inside the
top 30, and the split and merge dissimilarity ranges overlap almost completely
(0.17–0.92 vs 0.00–1.00). @david-spacil evidently read all 127. The one signal that did
work was the `aat_verdict` column added later: **3 of 3** `conflicting` groups split,
against 2–6 % for every other class. For the 9 new groups after reinstatement, rank by
`aat_verdict`, and do not repeat the "~30 rows" claim.

## 7. What actually blocks progress

**As of 4 September, nothing in the vocabulary is waiting on a person.** Both questions
that had stalled it were answered the same day, each against the artifact built for it:

- **O3/O4 → M11/M12.** @motyc ruled reinstate-with-guardrail (Q1) and bring-back-and-watch (Q2); @david-spacil agreed and endorsed the replacement wording. `6.O3O4.decision-package.md` and `reinstatement_preview.csv` did their job — the question was answered in terms of usable counts and token deltas, not impressions.
- **M8 → M13.** @david-spacil adjudicated all 127 groups: 7 splits, 120 merges. `collision_review.csv` did its job, though **not for the reason claimed** — see the correction in Phase 10.

**What remains is one build and one document.**

**The build** (ours, unblocked): six collision verdicts, then the reinstatement as a
single reviewable commit — twelve map values, two facet blocks, twelve `_exclusions`
entries removed, `geo_guardrail.active: false`, the `llm_run.py` wording, three
regression overrides, rebuilt artifacts and regenerated sheets. The drift gate and the
guardrail gate both refuse to let the halves separate, which is what makes @motyc's
"in the same change" a mechanism rather than a hope. One sub-question inside it belongs
to @david-spacil under M10: **which facets the reinstated terms land in** (§3,
`A1-facets`).

**The document** (ours, and now the sole critical path): **the D1 evaluation rubric.**
Nothing can be scored without it, no re-run of the bake-off means anything until it
exists, and the vocabulary is about to more than double — which raises the stakes
rather than lowering them. `6.D-eval.decision-package.md` frames five questions with
measured numbers; the reinstatement adds a sixth that is not optional: with 2 638
context terms in the enum, the rubric must say whether selecting a country or a
profession where the gold label is archaeological is *wrong* or *meta-text-adjacent*.
Without that, the first scored run after the rebuild is unreadable.

Two caveats sit under the evaluation, neither blocking:

- **The corpus is untracked.** Committing it — or publishing its checksum and provenance — is what turns one machine's evidence into the project's.
- **Quote `unique_*`, never the totals** from `corpus_branch_evidence.csv`. That mattered most on `heslar:zeme`, whose 7 occurrences are all `malta` = mortar. With Q1 now ruled, the finding changes role rather than disappearing: it predicts that the 981 reinstated geographic terms may never be correctly selected, and per-facet accuracy on `Cultural & Geographic Context` is exactly how "problems raise" would become visible.
