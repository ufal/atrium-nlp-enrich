## 🎯 Goal
Catch malformed TEITOK XML at the point of generation (end of `api_4_stats.sh`) so it never reaches downstream
visualizers, search indexes or the LINDAT release — the nlp-enrich counterpart of `atrium-translator`'s AMCR XSD gate.

## 🧭 Architecture (as built — supersedes the original xmllint/shell design)
1. **Pinned schema** — `schemas/teitok/teitok.xsd` (no `targetNamespace`, because the writer emits
   `<TEI xmlnsoff="http://www.tei-c.org/ns/1.0" lang="cs">`) + a trimmed local `xml.xsd`, provenance and the
   "how this schema went wrong once" history in `schemas/teitok/README.md`. **Hand-authored from
   `api_util/teitok_alto.py::write_teitok_merged()`** — no upstream TEITOK XSD/RNG/DTD exists in any of the
   TEITOK author's repositories, so there was nothing to vendor.
2. **Validator** — `api_util/validate_teitok_xml.py` (lxml, lazily imported; **not** the planned
   `validate_teitok_xml.sh`/xmllint): `rglob("*.teitok.xml")`, `[OK]`/`[FAIL]` + one diagnostic per violation,
   exit `0/1/2`, `--allow-empty`, `--quiet`, `--wellformed-only`; strips the TEI namespace first so legacy
   `xmlns=` documents validate against the same schema; points at `fix_teitok_bboxes.py` for the `</n>` quirk.
3. **Three emitters, three depths** —
   `stats` stage (`api_4_stats.sh` → `summarize_nt_udp.py` → `write_teitok_merged`): **full XSD, hard fail**
   before `atrium_paradata.py finish` (so `/enrich` fails too) ·
   flexiconv (`api_flexiconv.sh`): **well-formedness + `<TEI>` root only** ·
   `POST /rescale`: **advisory** `schema_valid`/`schema_errors` in the response (`null` = not checked).
4. **CI** — `.github/workflows/teitok-schema.yml`: schema compiles → committed samples pass → valid fixtures pass →
   **negative test** (`CTX_invalid` must be rejected) → `pytest tests/test_validate_teitok.py`, whose
   `TestRealWriterRoundTrip` runs the real writer and validates its output.

## ✅ What's settled
- Validator, schema, fixtures (`tests/fixtures/teitok/CTX_{valid,no_alto,invalid}.teitok.xml`), stage-4 hook,
  flexiconv hook, `/rescale` verdict and the named CI check all exist on `test`.
- The round-trip test is the part that matters: the first schema had a TEI `targetNamespace` and rejected **100% of
  real output** while every hand-written fixture passed; `TestRealWriterRoundTrip` now makes the writer the arbiter.
- CI install fixed after the first run died on a missing `pytest` (hub #10, G1).

## ⚠️ Found by the 2026-09-23 audit (not visible to this gate)
- **Circular contract** — an XSD derived from the writer accepts whatever the writer does. It passes output that
  upstream TEITOK readers misread: every `<tok>` on its own line with only `join="right"` (flexiconv/flexipipe/
  teitok2conllu/flexicorp read spacing from inter-token whitespace → 0 of 7 `SpaceAfter=No` survive a flexiconv
  round-trip), MWTs split into syntactic words, OntoNotes entities written `type="MISC" cnec="PERSON"`.
- **Schema enshrines defects** — `bboxType` allows negative coordinates (a side-effect of the PrintSpace shift, #9);
  `tok` is simple content, so a correct `<tok>…<dtok/></tok>` would be *rejected*; no `ord`, no `sameAs`, `cnec`
  required even for OntoNotes codes; every attribute set is closed, so any conformance fix must change the XSD in
  the same commit.
- **Stale committed samples** — `data_samples/TEITOK/*` use `xmlns=` + `xml:lang` and unshifted bboxes; they are not
  what today's writer produces, so the "samples are conformant" CI step validates artefacts, not the code.
- **Directory-wide gate vs. shared output dir** — `api_4_stats.sh` validates the *whole* `$TEITOK_OUTPUT_DIR` with the
  full XSD, and `api_flexiconv.sh` writes flexiconv output into the same directory (with names that can collide with
  the writer's): one converted document halts the next `stats` run.
