## 🎯 Goal

A born-digital PDF gets a TEITOK file with boxes:
- a `<surface>` per page, sized by the record's canvas;
- the line box on each `<lb>`;
- token boxes.

`layout_source` then reports `record`. A DOCX record, which has pages but no geometry, keeps the rows layout, and the README says so.

## 🔎 What the code does (`4f6ea4b`)

**Where the layout comes from.**
- Stage 4 takes a document's layout from `api_util/doc_identity.py:95` `layout_source()`: `{alto_dir}/{doc}.alto.xml`, else a flexiconv-converted TEITOK file, else `None`.
- `api_util/summarize_nt_udp.py:616` passes it to `write_teitok_merged()` (`api_util/teitok_alto.py:1300`).
- With `None`, the rows file is the layout: `<pb>`/`<lb>` without coordinates, and no `<surface>`.
- The service reports the source at `service/enrichment.py:703`: `layout=layout.kind if layout is not None else "rows"`.
- `layout_source` is a free string in the spec (`service/openapi.json:2514-2518`; `service/api.py:175`, "`alto`, `teitok` or `rows`"), so `record` is an additive value.

**The record already reaches stage 4, unused for layout.**
- `/enrich` takes it as the optional `document_json` part (`service/api.py:925`, read at `:938`).
- The service writes it as `baseline.document.json` and passes `--document-json` (`service/enrichment.py:606-617`).
- `run_pipeline.py:342-388` seeds a scratch directory with it.
- Stage 4 reads it as `{document_json_dir}/{doc}.document.json` (`summarize_nt_udp.py:633-640`), but only for the accretion hook, after the TEITOK is written.
- No code in `api_util/` or `service/` reads `pages[].canvas`.

**The record's geometry is normative** (`atrium_document.schema.json`):
- `$defs/bbox` is `[x_min, y_min, x_max, y_max]` with the origin top-left and y downwards, in the page's `pages[].canvas.unit`. That is TEITOK's convention.
- `lines[].bbox` (`:282`): on the digital-born path it is "the PDF adapter's native coordinates — the only bbox such a record will ever have". It has two writers, "mutually exclusive per document by source.origin".
- digital-convert writes `unit="pt"` and pdfplumber's `top`/`bottom` (`digital_pdf.py:34`, `:889`).

**What the writer needs** (the shape `_parse_alto()` returns, `teitok_alto.py:352`):
- `(strings, pages, graphics, blocks, meta)`;
- pages: `{id, width, height, idx, ps_*}`;
- strings: one per ALTO `String`, `{content, left, top, right, bottom, page_idx, block_id, line_id, line_bbox, lang}`.

Tokens are aligned to strings by content (`_align_tokens_to_alto`, `:507`). The `<lb>` box is the string's `line_bbox`. The precedent for a second source is `api_util/teitok_layout.py:125` `parse_teitok_layout()`, which returns the same 5-tuple and is dispatched from `_parse_alto()` (`teitok_alto.py:372-379`).

**Units.** `_build_page_scale_map()` (`teitok_alto.py:118`) tries three things in turn:
1. scale to a page image (`INPUT_PAGES_DIR`);
2. scale to `IMAGE_DPI` via `api_util/bbox_scale.py` `dpi_scale()`. Its `unit_per_inch()` (`:14`) knows `inch1200` and `mm10`, `pixel` goes through an ALTO DPI, and **`pt` falls through to 1.0**;
3. keep the source units and warn.

**The write-back guard.** `api_util/document_hook.py:382-392`: the `lines[]` merge is off (`include_lines=False`). nlp-enrich's grant there includes `bbox`, so enabling it must skip digital-born records.

**Tests.** `tests/test_teitok_conformance.py`:
- surface ids `facs-\d+` (`:218`);
- the XSD and the core lint (`:274`);
- the flexiconv round trip (`:298`, skipped without flexiconv).

Only `tests/test_document_originators.py` builds records with a canvas.

## 🔑 Decisions open (K4TEL)

1. **Word boxes.** The record has line boxes only. Either:
   - (a) apportion each line's box to its words by character offset (approximate, declared in the header), or
   - (b) give every token the line's box.

   Recommended: (a), because a TEITOK reader highlights a token by its box.
2. **Units.** Recommended: add `"pt": 72.0` to `unit_per_inch`, so `IMAGE_DPI` turns points into pixels. Page images rendered from the PDF are matched by tier 1. Without either, everything stays in points, with the existing warning.
3. **Page images.** The record has none. Write `pb@facs` only for pages with an image, as for ALTO (decision C of #38).

## ✅ Done when

- A PDF record from digital-convert `/reformat` and its text table go through `/enrich` to a TEITOK with one `<surface>` per page and boxed `<lb>` and `<tok>`, and `layout_source: "record"`.
- It passes `tests/test_teitok_conformance.py` and `validate_teitok_xml.py`.
- `entities[].bbox` is the union of the entity's token boxes, as on the ALTO path.
- A DOCX record keeps the rows layout.
- `service/README.md` "Layout inputs" (`:57`) lists the record as the third source.
