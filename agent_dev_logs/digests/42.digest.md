## 🎯 Goal

A born-digital PDF gets a TEITOK file with boxes: a `<surface>` per page sized by the record's canvas, the line box on each `<lb>`, and token boxes. `layout_source` then reports `record`. A DOCX record, which has pages but no geometry, keeps the rows layout, and the README says so.

## 🔎 What the code does today (`86b0277`)

**Where the layout comes from.**
- Stage 4 takes a document's layout from `api_util/doc_identity.py:95-105` `layout_source()`: `{alto_dir}/{doc}.alto.xml`, else a flexiconv-converted TEITOK file, else `None`.
- `api_util/summarize_nt_udp.py:616-631` passes that path to `write_teitok_merged()` (`api_util/teitok_alto.py:1300`).
- With `None`, the rows file is the layout: `<pb>` and `<lb>` without coordinates and no `<surface>` (module docstring, "Pages are layout-first").
- The service reports where the layout came from in one place: `service/enrichment.py:653`, `layout_source=layout.kind if layout is not None else "rows"`. The field is a free string in the spec (`service/openapi.json:2326-2330`, "`alto`, `teitok` or `rows`"), so `record` is an additive value.

**The record is already at stage 4, unused for layout.**
- `/enrich` takes the record as the optional `document_json` part (`service/api.py:918`). The service writes it as the run's baseline (`service/enrichment.py:589-601`), and stage 4 reads it as `{document_json_dir}/{doc}.document.json` (`summarize_nt_udp.py:633-640`), but only for the accretion hook, after the TEITOK is written.
- No code in `api_util/` or `service/` reads `pages[].canvas`.

**The record's geometry is normative** (`atrium_document.schema.json`):
- `$defs/bbox` is `[x_min, y_min, x_max, y_max]`, origin top-left, y downwards, in the page's `pages[].canvas.unit`. This is the TEITOK convention (`bbox_origin="page"`).
- `pages[].canvas` is `{width, height, unit}` (unit default `px`; a PDF page is `pt`).
- `lines[].bbox` on the digital-born path is "the PDF adapter's native coordinates — the only bbox such a record will ever have".
- digital-convert writes `unit="pt"` and pdfplumber's `top`/`bottom` (`api_util/digital_pdf.py:550-553`, docstring "Coordinates stay pdfplumber's `top`/`bottom` pair").

**What the writer needs** (the shape `_parse_alto()` returns, `teitok_alto.py:352-500`):
- `(strings, pages, graphics, blocks, meta)`;
- pages: `{id, width, height, idx, ps_*}`;
- strings: one per ALTO `String`, `{content, left, top, right, bottom, page_idx, block_id, line_id, line_bbox, lang}`.

Tokens are aligned to strings by content (`_align_tokens_to_alto`, `:507`). The `<lb>` box is the string's `line_bbox`.

The converted-TEITOK path is the precedent for a second source: `api_util/teitok_layout.py:125` `parse_teitok_layout()` returns the same 5-tuple, and `_parse_alto()` dispatches to it (`teitok_alto.py:374-379`).

**Units.** `_build_page_scale_map()` (`teitok_alto.py:118-226`) works in tiers:
1. scale to a page image when one is found (`INPUT_PAGES_DIR`);
2. otherwise to `IMAGE_DPI` via `api_util/bbox_scale.py` `dpi_scale()`, which knows `inch1200`, `mm10` and `pixel` (`unit_per_inch`), but not `pt`;
3. otherwise keep the source units and warn.

**Tests.**
- `tests/test_teitok_conformance.py` (ids include `facs-\d+` surfaces, `:218`; the XSD and core lint, `:274`; the flexiconv round trip, skipped without `flexiconv`, `:298`), `tests/test_teitok_pages.py`.
- Only `tests/test_document_originators.py` builds records with a canvas.
- Fixtures for born-digital PDFs are generated by digital-convert's `tests/fixtures/digital/make_fixtures.py` (`two_column.pdf`, `rich.docx`, `enrichable_pdf()`, …).

## 🔑 Decisions open

1. **Word boxes.** The record has line boxes only, and the writer aligns tokens to strings. Either:
   - (a) split each line into words and apportion its box by character offset (proportional, approximate), or
   - (b) give every word the line's box.

   Recommended: (a), stated as approximate in the header, because a TEITOK reader highlights a token by its box.
2. **Units.** Recommended:
   - add `pt` (72 per inch) to `bbox_scale.unit_per_inch`, so `IMAGE_DPI` turns points into pixels, and page images rendered from the PDF are matched by the existing tier 1;
   - without either, the surface and boxes stay in points, `<surface lrx lry>` in the same units, with the existing warning.
3. **Page images.** The record has none. As for ALTO without images: `pb@facs` is written only for pages that have an image, and no `facs` is invented (decision C of #38).
