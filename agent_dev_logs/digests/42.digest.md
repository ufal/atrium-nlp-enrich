## 🧭 Where it stands — 2026-10-15 (evening)

- **The record is the third layout source.** In order, stage 4 takes ALTO, then a flexiconv TEITOK, then `{document_json_dir}/{doc}.document.json`. The record counts when one of its pages has a canvas and a line on that page has a box.
- **The TEITOK** has:
  - a `<surface>` per canvas page and `<pb n>` from the page label (`i`, `ii`);
  - `lines[].bbox` on `<lb>`;
  - token boxes shared out from the line box by character offset (the header says so);
  - `lines[].group_id` as `<div type="TextBlock" subtype="page_header|page_footer|footnote">`.
- **The service:**
  - `layout_source: "record"`;
  - `/enrich` and `/jobs` take `document_json` without `file`: the record's `lines[]` are then the text.
- **Units:** points. `IMAGE_DPI` (CLI) turns them into pixels; `pt` = 1/72 inch in `bbox_scale.unit_per_inch`. Page images in `INPUT_PAGES_DIR` scale each page exactly. The service has no `IMAGE_DPI` (the env contract keeps it a batch knob), so it answers in points and `/rescale` with `scale` = DPI/72 converts.
- **A DOCX record** has no geometry: it still gets `rows`.

## 🔬 The AMČR check — E3, 2026-10-19 (digital-convert#5's extras job 7147054, dll-8gpu4)
- **Input:** CTX201100348's light record from C4 (55,028 bytes; 147 words; 90 pages), sent alone to `/enrich`, nlp-enrich `75d6dfc`, LINDAT live.
- **The TEITOK passed:**
  - `layout_source: "record"`, XSD valid;
  - 90 `<surface>`/`<pb>`;
  - `<lb>` 89, all boxed;
  - `<tok>` 179, 164 boxed;
  - 16 sentences, 19 `<name>`.
- **`/rescale` passed:** at 300/72 = ×4.166, 595×842 pt → 2479×3508 px; 353 boxes rescaled, 0 clamped, valid.
- **Not passed: `document_json` came back `null`.** Stage 4's paradata was its unfinished `.state_` file (listed first, no statistics). Reproduced exactly with the real service and runner, a stand-in LINDAT, and a Python 3.11 with only `requests` first on PATH.
  - The job started the service as `venv-nlp/bin/python -m service.api` without the venv on PATH. The stage scripts call `python3` from PATH and so ran the cluster's module Python.
  - Stage 4's TEITOK gate found no `lxml` and exited 5. It had already written the TEITOK, which the service re-validates itself, so it passed.
  - `run_pipeline.py` returned 5 before collecting the record, but ended with a bare `main()`: the process exited 0, and the service answered 200.
- **The same bug since `run_pipeline.py` was written:** every exit code in the README's table reached no caller. A LINDAT 503 came back as a 502 "silent empty run" (reason `null`), not v1.0.1-beta's `upstream_unavailable` (#41). Checked before and after the fix with the stand-in.
- **Fix, `v1.1.1-beta`:**
  - `sys.exit(main())`;
  - a virtual environment's `bin` goes first on the stages' PATH;
  - a preflight: the stages' `python3` must import `requests` (udp, nt) and `lxml` (stats, when it writes TEITOK), else exit 3 naming the interpreter and the `pip install`;
  - the service answers exit 3 as a 500 that leads with that line.

## 🎯 Goal

A born-digital PDF gets a TEITOK file with boxes:
- a `<surface>` per page, sized by the record's canvas;
- the line box on each `<lb>`;
- token boxes.

`layout_source` then reports `record`. A DOCX record, which has pages but no geometry, keeps the rows layout, and the README says so.

## 🔑 Decisions (K4TEL, 2026-10-15)

1. **Word boxes:** apportion each line box to its words by character offset, along the box's longer side. The header declares them approximate.
2. **Units:** `pt` in `bbox_scale.unit_per_inch`; `IMAGE_DPI` and page images scale. Without them, points with a warning.
3. **Page images:** as for ALTO: `<graphic url="{doc}-{N}.png">` and `pb@facs`, the names `INPUT_PAGES_DIR` matches.
4. **Scope (added):** the record alone is a valid `/enrich` input.

## 🔎 Findings while implementing (beyond the 10-08 design)

- `_Coords.fmt_str()` parsed boxes with `int()`, so the record's float line boxes raised. It parses floats now.
- `_header_xml()` took any layout with pages for ALTO ("Converted from ALTO file X.document.json" by `altoconvert`). It has a record branch now.
- **Hybrid records** (W3): ocr-postprocess replaces a flagged page's lines without `bbox`, and every dc#5 sample has `needs_ocr` pages with a canvas and no lines. Every record line is therefore a string, coordinate-free when it has no box, so its tokens keep page and line.
- **Page keys:** the hook keyed `entities[].page` and the `pages[]` merge by page index, so a record with labels `i`/`ii` would have gained rows "1"/"2". It now keys by the record's own label (`pages[].page_index` → `page`). Records without `page_index` behave as before.
- **Alignment window:** ±1000 characters. A client table that leaves out record lines (footers) drifts past it on long documents. The record-alone input removes this, and the README warns table senders.
- **The CreateAction:** the record is already the call's `object` whenever one is sent, so a record sent alone adds nothing more to it.
- **Untrustworthy lines:** `Garbage`, `Inverted` and `Trash` lines are left out of both the text and the layout, by one selection (`record_layout.text_lines`).
